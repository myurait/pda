## 試用で確かめていないこと

- 画面を人が見ていない。Codex は製品の API と CLI で試し、画面は応答を確かめただけの製品が多い。下の R5 と R14 の比べは、公式の README、文書、ソースによる。

- PC とスマホから開けることを、どの製品でも確かめていない。確かめたのは、ミニ PC の上での画面の応答と、公式の文書にある組み方と公開の手順までである。
- 2026-09-28 から 2026-10-04 の cezar の試用の途中まで、cccc が残した MCP の登録により、Codex のセッションに cccc の MCP サーバが付いていた (Orca、happier、OpenClaw、luvus、cezar の試用)。道具が 1 つ足されていただけで、試用の結果は変わっていない。

## R5 と R14 の比べ (残る不備の無い 8 本)

各項目は、公式の README、文書、ソースに記述があるかどうか。

- R5 の見渡しの画面
  - OpenClaw: セッションの一覧に状態の印。セッションごとに、途中の出力、ツールの呼び出しと出力のカード、実行時間。ファイルと差分の確認は会話とは別の面。
  - multica: issue を一覧、ボード、表、ガント、レーンで見る。実行ごとに、状態、時間、ツールの呼び出しを含む記録。
  - jean: プロジェクトごとの画面に、セッションのカード、状態、git と PR の状態。セッションごとに、ツールの呼び出し、経過時間、まとめ。差分の画面は会話と別。プロジェクトをまたぐ一覧は無い。
  - Orca: エージェントを「返事待ち、作業中、完了、休止」の列に並べる画面。カードに直近のメッセージと経過時間。ツールの呼び出しの一覧は無い。
  - cezar: プロジェクトをまたぐダッシュボードと、作業の一覧。途中の文、ツールの呼び出し、費用。経過時間の欄は無い。
  - herdr と collie: 返事を待っているものを先頭に並べる状態の一覧。中身は端末の出力そのもの。
  - luvus: エージェントの状態の一覧 (blocked、working、done、idle) と使用量。依頼や出力の欄は無い。
  - claw-orchestrator: ワークフローの実行の一覧と、検証の結果。普通のセッションは画面の一覧に出ない。
- R14 の途中の介入 (画面から、追加の指示、権限の確認への答え、やり直し、スマホから)
  - OpenClaw: すべてある。iOS の app に承認の受信箱がある。
  - Orca: すべてある。スマホの app から返事と追加の指示を送れる。
  - jean: 追加の指示と、セッションの行の承認のボタンがある。やり直しの機能は見つからない。スマホはブラウザ。
  - herdr と collie: 追加の指示と、エージェントの質問を押して答えるボタンがある。やり直しは無い。スマホはブラウザ (ホーム画面に置く形)。
  - multica: 追加の指示とやり直しはある。権限の確認は、作りとして自動で通す (答える場面が無い)。スマホの app は iPhone だけで、ストアに無く自分で作る。
  - cezar: 追加の指示はある。権限の確認に答える機能は予約だけで未実装。スマホはブラウザ。
  - luvus: 追加の指示とやり直しはある。権限の確認に答える機能は「まだ無い」と文書にある。
  - claw-orchestrator: スマホから使う面の記述が無い。

## プレビューの手順

3 本が決まったら、1 本ずつ次を行う。どれも各製品の報告の 6 節にある。

- **OpenClaw**
  - `oc config set gateway.controlUi.allowedOrigins` に公開の URL を入れて起こし直す。
  - Tailscale Serve は同じ機械の `127.0.0.1` から Gateway へ中継するので、`oc config set gateway.trustedProxies '["127.0.0.1"]' --strict-json` でその中継を信頼させる。入れないと、Gateway は中継された接続を 403 で断る。
  - `tailscale-pda serve --bg --https=19114 http://127.0.0.1:5114` で公開する。
  - 画面が「pairing required」になったら、ミニ PC で `oc devices list` と `oc devices approve <requestId>` で端末を承認する。
  - スマホの app は、同じ Gateway につなぐ。
- **Orca**
  - unit の `--pairing-address` を `https://pda-web.tailaff53a.ts.net:19113` にして起こし直す。
  - `tailscale-pda serve --bg --https=19113 http://127.0.0.1:5113` で公開する。
  - 起動時に記録に出るペアリング用の URL を、ブラウザか Mac の app で開く。ブラウザ用は起動の行の `pairing.webClientUrl`、Mac の app 用は `pairing.url` にある。URL には端末用のトークンが入っているので、チャットや記録に貼らない。スマホの app は、`--mobile-pairing` を付けて起こし直して出た URL でペアリングする。
- **jean**
  - `tailscale-pda serve --bg --https=19115 http://127.0.0.1:5115` で公開する。
  - unit は `--no-token` で、画面のログインが無い。Tailscale Serve は tailnet の端末からしか届かないので、プレビューはこのまま行う。OpenClaw の `auth.mode=none` も同じ扱い。

権限の確認を出すには、各製品で次のように切り替える。

- **OpenClaw:** Claude Code は常に `--permission-mode default` と `--permission-prompt-tool stdio` で起こされ ([cli-runtime-args.ts](https://github.com/openclaw/openclaw/blob/main/extensions/anthropic/cli-runtime-args.ts))、権限の確認は Gateway が受ける。切り替えは無い。確認が画面に出て答えられるかは、プレビューで確かめる。
- **Orca:** 設定の Agents にある Agent Permissions を Yolo から Manual にする。以後に開く端末の Claude と Codex が、権限を省く引数なしで起こされる。
- **jean:** チャットの欄の権限の選択を Full access から Supervised にする。選択はセッションごと。

プレビューでは、各製品で次の 3 つを確かめる。

- スマホと PC から開けること。
- 全体を 30 秒見て、誰が何をしているかが読めること (計画 5.2 の S5)。
- スマホから、止める、追加の指示を送る、権限の確認に答える、の 3 つができること (S6)。権限の確認に答えるには、権限の確認を省く設定を外して動かす。
