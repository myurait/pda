# v0.3 の決定: OpenClaw

- 更新: 2026-10-11 JST
- 計画: [plan-v0.3.md](../plan-v0.3.md) の 5.1 の 8 (1 本の決定と切り分け)。オーナーの判断は計画の 8 節

## 決定

PDA のフロントドアと可視化層に、OpenClaw (https://github.com/openclaw/openclaw) を使う。

## 決めた理由

- 必須の条件 (R1、R2、R4、R7、R13) を試用で満たした。Claude Code は手を加えていない実行ファイルを `--print` の stream-json で、Codex は `codex app-server` で動かす。最新の版 (Claude Code 2.1.293、Codex 0.161.0) でも通った ([評価](v0.3-openclaw-evaluation.md))。
- 見渡し (R5) と途中の介入 (R14) の記述が、比べた製品の中でいちばんそろっている ([3 本の提案](v0.3-shortlist.md))。
- 役ごとに指示・skill・MCP の道具・hook を分けられる (R3)。統率役、作業者、監査役の 3 つのエージェントで確かめた ([評価](v0.3-openclaw-evaluation.md) の R3 の節)。
- 作業の段ごとの plugin の hook と、判定モデルの役 (`decisionModel`、Jev を使える) を持つ ([findings.md](../research/front-door-oss-2026-09-27/findings.md) の 14 節)。
- ほかの候補は、オーナーのプレビューと追加の確認で外れた。
  - Orca: エージェントを端末で動かす製品で、フロントドアがチャットでない。
  - jean: 作業がリポジトリ単位で、プロジェクトをまたいで頼む使い方に合わない。
  - cccc: 複数のエージェントをチームとして協調させる土台で、チャットには連絡だけが出て作業の様子は端末に出る。上流の変化への追従で、修正が利用者に届くまで 5 日以上かかる (findings.md の 12 節と 13 節)。

## 要件ごとの切り分け

「OSS」は OpenClaw のまま満たすもの、「設定」は設定・skill・plugin で満たすもの、「開発」は作り足しが要るもの。

- R1 フロントドアがチャットで、Claude Code と Codex を切り替えられる: OSS。試用で確かめた。
- R2 他のエージェント環境に仕事を渡せ、渡した先が見える: OSS。`sessions_spawn` で両方向に渡せた。統率役が子の結果を読む段で `Gateway client authority closed` の誤りが出たことがある。画面と同じく接続をつないだままにした形、途中で切った形、別の身元でつなぎ直した形の 5 回では出ず、条件は特定していない ([評価](v0.3-openclaw-evaluation.md))。同じ確認で、子を 1 回動かしたあと作業者のモデルが使えない状態になり、OpenClaw を起こし直すまで次の受け渡しが断られることが 4 回あった。
- R3 実行単位ごとに skill・hook・MCP・プロンプトを絞る・足す: 設定。エージェントごとの `AGENTS.md`、共通の skill の置き場と使える skill の一覧、道具の禁止の設定 (`tools.deny`)、セッションごとの MCP の有効・無効で分けられた。全エージェントに共通の指示を 1 か所から配る設定は無く、小さな plugin (`before_prompt_build` で 1 つのファイルを読んで足す) が要る。hook をエージェントに絞るには、plugin の中で `ctx.agentId` を見て分ける。
- R4 ミニ PC に常駐し、PC とスマホから届く: OSS と設定。Tailscale Serve で公開するには `gateway.trustedProxies` に `127.0.0.1` を入れる。スマホからの操作はオーナーのプレビューで判断する。
- R5 見渡し: OSS。30 秒で読めるかはオーナーのプレビューで判断する。
- R6 止まるときの報告と、報告と別の成果物の一覧: 資料ではファイルと差分の面が会話と別にある。確かめていない。
- R7 途中で止める: OSS。`chat.abort` で、Claude は 0.01 秒、Codex は 0.004 秒で止まった表示になった。
- R8 会社と個人のアカウントを同じ一覧に並べる: 設定 (資料)。エージェントごとに認証とモデルを持てる。確かめていない。
- R9 出来事を外に出す: OSS (資料)。OpenTelemetry を内蔵する。確かめていない。
- R10 保守と追従: リリースの間隔は 3〜7 日で、新しいモデルへの対応はおおむね 1〜2 日。5 日以上かかった例がある。GPT-6.1 Sol への対応は主の系列で 9 日かかり、Claude Code の前景の Bash を背景に回すと返事が届かない不具合 ([#157647](https://github.com/openclaw/openclaw/issues/157647)) は報告から 16 日開いたまま (findings.md の 12 節)。
- R11 起動時に読み込む道具と MCP を絞る: 設定 (資料)。エージェントごとの道具の一覧と許可の設定で絞れる。
- R12 実行器の起動と停止を画面から: OSS (資料)。
- R13 途中の出力: OSS。途中の文とツールの実行が届く。
- R14 途中の介入: OSS (資料)。実行中に追加の指示を送る操作と、権限の確認に答える操作 (資料では iOS の app に承認の受信箱がある) は、確かめていない。

## 個人利用の外のアカウントがある場合の使い方

PDA は、個人の契約に加えて、会社の契約のアカウントと会社のコネクタ (課題管理、監視、DB の参照、社内のクラウドの操作など) を使う前提で組む。

### 置き場所と橋渡し

- フロントドアの OpenClaw はミニ PC に置く。会社のコネクタはミニ PC につながず、開発 PC の Claude だけが使う。
- ミニ PC の入口からは、OpenClaw の node (開発 PC を node としてつなぎ、`exec host=node` で開発 PC の `claude -p` を動かす) か MCP で、開発 PC の Claude に頼む。node の経路は、途中の出力が順に届き、取り消すと開発 PC の処理が止まる作り (資料)。この橋渡しはまだ作っていない。
- 開発 PC の Claude はフルアクセスで動かす。戻しにくい操作の承認は、入口に頼む前の会話で取る。
- 開発 PC の Claude には、オーナーの伝え方の規約は要らない。ユーザー設定の hook (通知、伝え方の点検) を外し、会社のリポジトリのプロジェクトの設定だけを残す形で起こす。
  - `--setting-sources project,local` で `user` を外すと、ユーザーの範囲に登録した MCP (`~/.claude.json` にあるもの)、claude.ai のコネクタ、ユーザーの skill (`~/.claude/skills`) が、どれも読み込まれない。plugin の MCP は読み込まれる (2026-10-11、Claude Code の起動時の情報で確かめた)。claude.ai のコネクタは `--mcp-config` では渡せない。
  - `user` を残して hook だけを止める (`--settings '{"disableAllHooks": true}'`) と、MCP、claude.ai のコネクタ、skill はすべて読み込まれ、hook は動かない。ユーザーの `CLAUDE.md` (伝え方の規約を含む) は読み込まれる。
  - プロジェクトの設定は、作業フォルダが会社のリポジトリのときだけ効く。呼ぶ側が作業フォルダを必ず指定する形にする。
- OpenClaw の node は Node.js 24.16 以上か 26.1 以上を要る。開発 PC の Node.js は 22.21 で、node をつなぐには新しい Node.js が要る。
- 会社のリポジトリはミニ PC に置いてよい。コードを読む・直す・設計の文書を書く作業は入口側で行い、開発 PC を経由するのはコネクタを使う作業だけにする。
- 組織が個人のアカウントに紐づく形の GitHub は、会社のコネクタに含めない。PR のレビューや作成は入口側で行う。
- 会社のコネクタを使う作業は、1 件ごとに入口と開発 PC の 2 つのセッションの枠を使う。
- iOS の開発 (Xcode、シミュレーター) は Mac にしか道具が無いので、会社かどうかにかかわらず開発 PC の Claude に頼む。開発 PC の desktop app にしか無い道具 (シミュレーターの画面操作、ブラウザの操作、他のチャットの履歴を読む道具) は、呼ばれる側の Claude では使えず、`xcrun simctl` などの CLI で代える。

### 役と規約

- エージェントを、作業の持ち主となる統率役、作業者、監査役に分ける。
- オーナーの規約はミニ PC 側に置き、どのモデルからも使える文として渡し、エージェントの役か契約アカウントで適用を分ける。
  - 伝え方の規約 (出来上がった文で確かめられるもの) は監査役に割り当てる。
  - 作業中の振る舞いの規約 (承認を待つ、自分で確かめられることを返さない、など) は作業者に割り当てる。
- 判定モデル (Jev) は、判断の材料を足す使い方をする。判定を依頼者の指定より優先させる仕組みと、委譲や道具の呼び出しを止める仕組みは作らない ([開発の考え方: 進める機能と止めるための機能](../process/progress-over-stopping.md))。

### 作業の種類ごとの変わり方

- 設計: 課題管理の更新は開発 PC の Claude に頼む。設計の文書の編集は入口側で行う。
- 不具合の調査: 監視や DB を調べる作業は開発 PC の Claude が行い、入口は振り分けと報告を受け持つ。
- リリースの確認: GitHub の確認は入口側、課題管理・監視・DB の確認は開発 PC 側で行う。
- PR のレビュー: 入口側で行う。
- 並行作業: 今は別々のチャットを人がつないでいる。OpenClaw では、別のセッションに `sessions_spawn` で仕事を渡す形になる。
