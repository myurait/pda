## 結論

T1〜T5 と T9 は通った。必須の条件のうち、R1、R2、R7、R13 をミニ PC の上で確かめた。R4 は常駐と画面の応答までを確かめ、PC とスマホからの到達はオーナーのプレビューで確かめる。操作はすべて、画面が使う Gateway の WebSocket API で行い、ブラウザの画面そのものは見ていない。

- T2、T4: Claude Code は Gateway が直接起こし、途中の説明とツールの実行が届いた。Codex は Gateway が起こした `codex app-server` で動き、説明が増分で届いた。

## R3 の確認 (2026-10-11)

- 対象: ブランチ `v0.3/r3-openclaw` で足した報告の 9 節と証拠 [evidence/v0.3-openclaw/2026-10-11-r3/](evidence/v0.3-openclaw/2026-10-11-r3/)。指示は [R3 の確認の指示](../codex-runs/2026-10-11-v0.3-r3-openclaw.md)
- 走行: 31 分、turn 1、goal は complete

統率役 (`r3-leader`、Claude Code)、作業者 (`r3-worker`、Codex)、監査役 (`r3-auditor`、Claude Code) の 3 つのエージェントを作り、指示・skill・MCP の道具・plugin の hook を役ごとに分けられた。1 か所の正本から配れたのは、skill (全エージェント共通の置き場) と MCP の定義。全エージェントに共通の指示は製品の設定だけでは配れず、`before_prompt_build` で 1 つのファイルを読んで足す小さな plugin を作って配れた。

- 指示: エージェントごとの `AGENTS.md` の決まり (返事の 1 行目の役の印) が、それぞれの返事に出た。統率役が `sessions_spawn` で起こした作業者の子も、作業者の印で返した。
- skill: 作業者の作業場所の skill は作業者だけが使えた。共通の置き場の skill を書き換えると、3 つの新しいセッション全部に届いた。監査役の skill の許可の一覧を空にすると、共通の skill も見えなくなった (設定の反映後)。
- MCP: 定義は 1 つで、作業者と監査役から道具の禁止の設定 (`tools.deny`) で外せた。1 つのセッションだけで無効にすることもできた。画面の「This session」で 1 つのセッションだけ有効にする操作は、採取側の設定の誤りで確かめられなかった。
- hook: 1 つの plugin が `ctx.agentId` で分岐し、作業者の `date` の実行だけを止め、監査役だけに文脈を足した。Claude Code の内蔵の道具 (Bash、Edit、Read) と Codex の内蔵の道具 (シェル、`apply_patch`) の呼び出しが、どちらも `before_tool_call` に届いた。`before_prompt_build` と `agent_end` は両方の実行器で呼ばれ、`before_agent_run` は Claude Code でだけ呼ばれた (資料の説明と同じ)。
- 判定モデル: 入っている版 (2026.9.8) に、エージェントごとの `decisionModel` の設定、`decision_evaluate` の道具、plugin から呼ぶ `api.runtime.decisions.evaluate` があった。判定モデルは設定せず、呼んでいない。

残る問題:

- 統率役が、起こした作業者の子の結果を受け取る段で `Gateway client authority closed before dispatching sessions.resolve.` が出て、結果を引用できなかった。原因は特定していない。
- 役の印は短い質問では守られたが、すべての返事で守られるわけではなかった。
