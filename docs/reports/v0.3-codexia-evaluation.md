## 結論

T1〜T5 は通った。T9 (Claude Code と Codex の間で仕事を渡す) は、製品の機能に無かった。必須の条件のうち、R1、R7、R13 をミニ PC の上で確かめた。R2 は、製品の機能では満たさない。R4 は常駐と画面の応答までを確かめ、PC とスマホからの到達はオーナーのプレビューで確かめる。

- T2、T4: Claude Code は、製品が使う Rust の crate (`claude-agent-sdk-rs`、作者は codexia と同じ) が PATH の `claude` を `--output-format stream-json --input-format stream-json` で起こした。Anthropic の Agent SDK でも ACP の adapter でもない。Codex は `codex app-server` で動いた。途中の説明とツールの呼び出しが WebSocket で届いた。Claude の途中の出力は、文字の増分ではなく、説明やツールの呼び出しの単位で届いた。
- T3、T5: 製品の interrupt の API で、Claude は 0.009 秒、Codex は 0.008 秒で中断の結果が返った。
- T9: 製品の Bot の機能 (`ask_bot`) は ACP のエージェントにしか渡せず、一覧は keke と Claude の ACP adapter だけで、Codex は無い。Claude Code (crate の経路) と Codex の間で渡す機能は無い。
- 画面には、手元 (loopback) からはログインなしで入れる。別の端末からは、保護された API が端末のトークンを求める (HTTP 401、「device token required」)。
