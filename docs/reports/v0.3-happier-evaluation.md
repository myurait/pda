## 結論

選別は終わっていない。T1〜T5 は通ったが、Claude Code の試用は、ミニ PC の端末から入力する経路 (local) でしか行っていない。画面やスマホから Claude に頼む経路を確かめ直す。

- T2、T3: Claude Code は、ミニ PC の端末で起こした happier の CLI の中で動き、途中の出力が Web の画面に映った。`session stop` で 1.7 秒で止まった。
- T4、T5: Codex は daemon が `codex app-server` で起こし、Web の画面に途中の出力が出た。`session stop` で 1.4 秒で止まった。
- T9: Claude Code から Codex へは、製品の subagent の委譲で渡せ、渡した先の途中のコマンドが画面に出た。Codex から Claude Code への委譲は、製品の中の SDK の経路 (`ClaudeSdkAgentBackend`) に固定されていて、試していない。
- 画面の入力欄から local のセッションへ送ると、happier は Agent SDK の経路 (remote) へ切り替える (報告の 4 節、導入済みのコードで確認)。Agent SDK の経路は H7 で使わないので、この経路は試していない。

## 確かめ直すこと

公式文書には、Agent SDK を使わずに、画面から Claude Code の端末の画面へ入力を書き込む「unified terminal」の経路がある ("Run Claude Code once, in a real terminal that Happier and you both drive, instead of running a separate Agent SDK process behind the app."、[Claude unified terminal](https://docs.happier.dev/sessions/claude-unified-terminal))。

- Claude Code を動かす端末は、Linux では tmux か、happier に同梱の zellij。既定の「Auto」は tmux があれば tmux を使う。tmux に依存しないように、zellij を選んで試す。
- サーバの機能フラグで開ける機能で、Settings → AI backends → Claude Code の「Use unified terminal runtime」で使う。

この経路で、画面から Claude Code に頼み、止め、Codex から Claude Code へ渡せるかを、追加の指示 [2026-10-02-v0.3-setup-happier-unified.md](../codex-runs/2026-10-02-v0.3-setup-happier-unified.md) で 1 回走らせる。

- 報告書は指示の節の順で、各試用に証拠のファイルが付き、失敗の文と試した回数が残っている。local の経路を保つ決まりを守り、remote へ切り替わる操作を避けたことを書いている。
