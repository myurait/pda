## 結論

選別は終わっていない。T1〜T5 は通ったが、Claude Code の試用は、ミニ PC の端末から入力する経路 (local) でしか行っていない。画面やスマホから Claude に頼む経路を確かめ直す。

- T2、T3: Claude Code は、ミニ PC の端末で起こした happier の CLI の中で動き、途中の出力が Web の画面に映った。`session stop` で 1.7 秒で止まった。
- T4、T5: Codex は daemon が `codex app-server` で起こし、Web の画面に途中の出力が出た。`session stop` で 1.4 秒で止まった。
- T9: Claude Code から Codex へは、製品の subagent の委譲で渡せ、渡した先の途中のコマンドが画面に出た。Codex から Claude Code への委譲は、製品の中の SDK の経路 (`ClaudeSdkAgentBackend`) に固定されていて、試していない。
- 画面の入力欄から local のセッションへ送ると、happier は Agent SDK の経路 (remote) へ切り替える (報告の 4 節、導入済みのコードで確認)。Agent SDK の経路は H7 で使わないので、この経路は試していない。

## 確かめ直すこと

公式文書には、Agent SDK を使わずに、画面から Claude Code の端末の画面へ入力を書き込む「unified terminal」の経路がある ("Run Claude Code once, in a real terminal that Happier and you both drive, instead of running a separate Agent SDK process behind the app."、[Claude unified terminal](https://docs.happier.dev/sessions/claude-unified-terminal))。

- Claude Code を動かす端末は、Linux では tmux か、happier に同梱の zellij。既定の「Auto」は tmux があれば tmux を使う。tmux に依存しないように、zellij を選んで試す。
- サーバの機能フラグで開ける機能で、Settings → AI backends → Claude Code の「Use unified terminal runtime」で使う。

この経路で、画面から Claude Code に頼み、止め、Codex から Claude Code へ渡せるかを、追加の指示 [2026-10-02-v0.3-setup-happier-unified.md](../codex-runs/2026-10-02-v0.3-setup-happier-unified.md) で 1 回走らせる。

## 指示の出来

- 報告書は指示の節の順で、各試用に証拠のファイルが付き、失敗の文と試した回数が残っている。local の経路を保つ決まりを守り、remote へ切り替わる操作を避けたことを書いている。
- 設計側の見落とし: 製品ごとの指示で「local の経路で動かす」と決めたが、local は画面から入力すると remote へ切り替わる。画面から頼めることが要件 (R1、R4) なので、画面から頼めて Agent SDK を使わない経路を指示に書くべきだった。
- 待ち受けは `127.0.0.1:5112` で、happier 自身のアカウント (端末の鍵) が画面のログインに要る。別の端末から開くときは、Settings → Add your phone と、新しい端末での Login / Restore account でペアリングする (報告の 6 節)。

## 追加の走行 (2026-10-04)

- 対象: ブランチ `v0.3/setup-happier-2` で足した報告の 8 節と証拠 [evidence/v0.3-happier/2026-10-02/](evidence/v0.3-happier/2026-10-02/)。指示は [追加の指示](../codex-runs/2026-10-02-v0.3-setup-happier-unified.md)
- 走行: 30 分、turn 1、goal は complete。コマンドの失敗 3 件はいずれも途中の試行で、報告に経緯がある

画面と同じ API から、unified terminal の経路で Claude Code に頼めた。Claude Code は happier に同梱の zellij の中で、手を加えていない実行ファイルとして動き (stream-json の引数なし)、ログの runtime は `unified-terminal` で、Agent SDK の経路は使われていない。tmux は使っていない。

- T2: 1 回目の依頼は、途中の出力が画面に出て、編集まで終わった。同じセッションへの 2 回目の依頼は「Terminal draft is blocking delivery」で止まり、画面の Clear composer も 2 回とも失敗した。端末の入力欄には「変更をコミットして」という文が出ていた。Claude Code が入力欄に出す次の依頼の候補を、happier が書きかけの文と読んでいるように見えるが、確かめていない。
- T3: 画面の入力欄の停止ボタン (セッションごと止める `session stop` ではない) で、0.305 秒で `Aborted by user` が出た。Claude Code のプロセスは残り、次の依頼を待つ状態に戻った。
- T9: Codex から Claude Code への委譲は試していない。委譲先は製品の `ClaudeSdkAgentBackend` に固定されている。これは製品が自分で書いた実行器で、利用者の `claude` の実行ファイルを `--output-format stream-json` で起こす (`apps/cli/src/backends/claude/sdk/query.ts` の 330 行目、`sdk/utils.ts` の 323〜330 行目)。Anthropic の Agent SDK ではなく、OpenClaw の claude-cli バックエンドと同じ形で、H7 には当たらない。追加の指示が委譲先にも unified terminal を求めたため、Codex は試さなかった。設計側の指示の誤りである。
