## 5. 認証

unit の HOME は `/home/user/v03/agent-home`、Claude には `CLAUDE_CONFIG_DIR=/home/user/pda/secrets/claude`。PATH の先頭は `/home/user/.local/bin`。`CODEX_HOME` は unit に設定せず、`UnsetEnvironment=CODEX_HOME` で継承も除いた。手動起動時は `env -u CODEX_HOME` を使用した。

agent-home の `.claude` と `.codex` が指定の認証複製先への symlink であることをメタデータのみで確認した。CLI の既存ログインで両者が応答し、API キーや新たなベンダーログインの入力は要求されなかった。認証ファイルの内容は読まず、表示・コピー・手作業の編集もしなかった。Luvus の状態ディレクトリのファイル名を調べた範囲では CLI 認証の新たな複製は見つからなかった。

Luvus Web 自体には一回限りのペアリングがある。起動時のリンクを5分以内に1回開き、そのブラウザタブに保持される ticket で接続する。私有ログ `/home/user/v03/luvus/web-console.log` は0600。証拠にはリンクの秘密部分を保存せず、WebSocket の ticket も値を伏せた。unit の status から秘密値が出ないよう、bridge の標準出力・標準エラーをこのログへ向けている。

## 6. 人の手順

この導入・試用に root が必要な手順はなかった。以下の公開操作は未実施。

### ローカル画面とログイン

```sh
systemctl --user start v03-luvus.service
awk '/#pair=/{last=$0} END{print last}' /home/user/v03/luvus/web-console.log
```

表示された最新の `http://127.0.0.1:5111/#pair=<一回限りの値>` を5分以内に1つのタブで開く。素の URL は `http://127.0.0.1:5111/`。SSH 転送は設計側で用意する。別タブ・別デバイスは、接続済み画面の Devices から新しいリンクを発行する。未接続のままリンクが失効した場合、この unit は対話 stdin を持たないため `systemctl --user restart v03-luvus.service` で再発行する。この再起動は実行中の pane も停止する。

### Tailscale Serve

指定された公開コマンドは次のとおり。

```sh
/home/user/.local/bin/tailscale-pda serve --bg --https=19111 http://127.0.0.1:5111
```

加えて、Luvus は接続先 Host と WebSocket Origin を検査するため、公開 URL を unit に指定する必要がある。[公式 Web 文書](https://luvus.dev/docs/guides/web/)に従い、`systemctl --user edit v03-luvus.service` で次の override を設定する。`<このマシンのTailscale DNS名>` は実際の名前に置き換える。

```ini
[Service]
ExecStart=
ExecStart=/home/user/v03/luvus/luvus web --control --port 5111 --no-open --public-url https://<このマシンのTailscale DNS名>:19111 --origin https://<このマシンのTailscale DNS名>:19111
```

その後 `systemctl --user daemon-reload` と `systemctl --user restart v03-luvus.service` を実行する。公開画面は `https://<このマシンのTailscale DNS名>:19111/`。ログの最新のペアリングリンクでログインする。ポート転送だけでは Luvus の Host/Origin 設定は変わらない。

終了時は `systemctl --user stop v03-luvus.service`。unit の `ExecStop` が Luvus server と pane を止め、cgroup の残りも終了する。導入物と状態は残る。

- Web の全ボタンや全操作は確認していない。T2〜T5 と T9 の依頼・中断・出力は製品のローカル API/CLI で確認した。
- T4 初回の購読は `subscriber_overflow` で途中終了した。文書に記載された有界キューの超過という通知を受けたが、詳細な原因は未特定。購読範囲を小さくした1回の再試行では完了まで取得できた。初回の未取得区間を補完した記録とはしていない。
- T9 で見えたタイトルによる Codex/Claude の取り違えは、当該タイトル・セッションでの観測。検出ルールや製品コードは変えず、新規 pane で一度だけ試し直した。別のタイトルや長期利用での再発範囲は未確認。
