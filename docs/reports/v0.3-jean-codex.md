## 3. 試用の結果

証拠はすべて [evidence/v0.3-jean/](evidence/v0.3-jean/) にある。T2・T4 の依頼本文は指定の日本語をそのまま送り、実行モードは `yolo`、モデル指定は Claude が `sonnet`、Codex が Jean の既定モデル `gpt-5.6-sol`。API クライアントは Node の WebSocket を使用し、受信時刻を各イベントに付けた。

### T1 導入と常駐

- やったこと: 公開バイナリを展開し、指定の環境変数と user unit で起動した。
- 起きたこと: 1回の起動で `active (running)`。`127.0.0.1:5115` の待ち受け、画面の HTTP 200、`/healthz` と `/readyz` の正常応答を確認した。他の `v03-*.service` は開始前にすべて停止中だった。
- 証拠のファイル名: `00-preflight.txt`、`01-install.txt`、`01-unit.txt`、`01-listen.txt`、`01-api-setup.txt`。

### T2 Claude Code に頼む

- やったこと: scratch の base session を作り、`send_chat_message` で指定の依頼を送信した。

## 4. Claude Code と Codex の起動のされ方

Jean 本体は PID 278072、親は user systemd の PID 1274。T2 の主 Claude は PID 278762、T4 再試行の Codex は PID 279450 で、観測時はいずれも親 PID 1274 だった。製品のソースは、一時的なシェルからバックグラウンド起動する実装である。親子関係を Jean の直下と読み替えてはいない。

Claude の主な実引数は `--print --output-format stream-json --input-format stream-json --verbose --tools default --include-partial-messages --model sonnet --permission-mode bypassPermissions`。Jean が `--add-dir`、`--allowedTools`、`--mcp-config`、`--strict-mcp-config`、システムプロンプト等も付けた。実際の引数一覧は `06-ps-claude.txt` にあり、MCP の秘密値は伏せている。

指定ファイルが手がかりとして挙げた `jean-core/src/claude_cli/config.rs` は、今回の版では CLI の選択処理だった。PATH 解決は [同ファイル113〜159行](https://github.com/coollabsio/jean/blob/8ce1712bbe310db61161110a6de813d882ea4e83/jean-core/src/claude_cli/config.rs#L113)、stream-json の引数構築は [chat/claude.rs 675〜689行](https://github.com/coollabsio/jean/blob/8ce1712bbe310db61161110a6de813d882ea4e83/jean-core/src/chat/claude.rs#L675)、起動呼び出しは [同1462〜1471行](https://github.com/coollabsio/jean/blob/8ce1712bbe310db61161110a6de813d882ea4e83/jean-core/src/chat/claude.rs#L1462)、シェル起動は [chat/detached.rs 309〜339行](https://github.com/coollabsio/jean/blob/8ce1712bbe310db61161110a6de813d882ea4e83/jean-core/src/chat/detached.rs#L309)。この試用の Claude 経路は Agent SDK・ACP adapter を経由していない。

Codex の実引数は `/home/user/.local/bin/codex app-server --listen unix:///home/user/v03/jean/data/codex-app-server.sock`。製品の起動処理は [chat/codex_server.rs 888〜909行](https://github.com/coollabsio/jean/blob/8ce1712bbe310db61161110a6de813d882ea4e83/jean-core/src/chat/codex_server.rs#L888)。モデル・依頼・権限は app-server に渡すため ps の引数には現れない。Yolo は [chat/codex.rs 803〜807行](https://github.com/coollabsio/jean/blob/8ce1712bbe310db61161110a6de813d882ea4e83/jean-core/src/chat/codex.rs#L803) で `approvalPolicy=never`、`sandbox=danger-full-access` に設定する。

T2 では PID 278729、T4 では PID 279430 の別 Claude プロセスが Jean PID 278072 の子として観測された。引数は `--print --input-format stream-json --output-format stream-json --verbose --tools default --model sonnet --no-session-persistence --max-turns 1`。これは [セッション命名処理](https://github.com/coollabsio/jean/blob/8ce1712bbe310db61161110a6de813d882ea4e83/jean-core/src/chat/naming.rs#L426) と対応し、Codex を選んだターンでも Claude CLI が起動した。

## 5. 認証

製品プロセスの `HOME=/home/user/v03/agent-home`、`CLAUDE_CONFIG_DIR=/home/user/pda/secrets/claude`、PATH の先頭を `/home/user/.local/bin` とした。`CODEX_HOME` は unit の `UnsetEnvironment` で外し、手動 CLI も `env -u CODEX_HOME` を使用した。HOME の `.claude`、`.codex` は事前配置された認証ディレクトリへの symlink。子プロセスでも指定の HOME・Claude 設定先・CODEX_HOME 未設定を確認した。

Jean の `check_claude_cli_auth` と `check_codex_cli_auth` は両方 `authenticated=true`。API キーの入力やログインのやり直しを求められず、Web は公式オプション `--no-token` でログイン操作なしだった。保護対象の認証ファイル・設定ファイルを直接読んだり、複写・手編集したりしていない。CLI 自身の信頼設定と、製品の標準 MCP 登録 API、終了時の CLI 登録解除のみを使用した。

T9 で製品が Codex に登録した名前は `jean`。登録先は `/home/user/v03/agent-home/.codex/config.toml`、製品が作った backup は `/home/user/v03/agent-home/.codex/config.toml.bak.1791107153`。backup は `ls -l` のメタデータだけを記録した。Claude はセッション限りの `--mcp-config` 注入で、永続登録は追加しなかった。

試用後の09:52:26 UTCから `systemctl --user stop v03-jean.service` を実行し、`inactive/dead`、`MainPID=0`、ポート5115の待ち受け消滅、停止直前の unit 内7プロセスの消滅を確認した。`codex mcp remove jean` で登録を解除し、`codex mcp list` は登録なし、`claude mcp list` は `claude.ai Claude Docs` のみで Jean 登録なしだった。上記 backup と、新しく作られた `/home/user/v03/agent-home/.cache/jean/` を削除し、試用用 tmux サーバが残っていないことを確認した。認証本体と `settings.json`・`config.toml` の手編集・削除はしていない。製品配下および agent-home のファイル名・メタデータ調査では、CLI 認証の追加複製は見つからなかった。製品・unit・scratch・製品データは残してある。終了時のコマンドと登録一覧は `10-cleanup.txt`。

## 6. 人の手順

この試用を完了するために root 作業は不要だった。Jean の Codex 検出 API は `Codex sandbox requires bubblewrap. Install it with: sudo apt install bubblewrap` を返した。sandbox 付きモードを試す場合の system package 導入は人が行う手順で、今回は実施していない。

```sh
sudo apt install bubblewrap
```

再開と Tailscale Serve 公開は次の順に行う。この走行では Serve を設定していない。

```sh
systemctl --user start v03-jean.service
/home/user/.local/bin/tailscale-pda serve --bg --https=19115 http://127.0.0.1:5115
```

Serve が表示する HTTPS URL の `/` をブラウザで開く。今回の unit は `--no-token` のため製品のログイン・トークン入力は不要で、到達できる端末の範囲は既存の Tailscale 設定による。直接接続先は `http://127.0.0.1:5115/`。自動起動も必要になった場合は `systemctl --user enable v03-jean.service` を人が実行する。

T9 を再現する場合は、試用後に解除した Codex の Jean MCP 登録を製品の設定から戻す。今回と同じ登録対象を使う API 操作は次のとおり。Claude 側の MCP は実行時に製品が渡す。

```sh
node /home/user/v03/jean/run/rpc.mjs install_jean_mcp_config '{"backends":["codex"],"mode":"current"}'
```

登録時に製品が `config.toml` の backup を作る。試用後は今回と同じく CLI で `jean` 登録を外し、その回に作られた backup を除く。
