## 次の指示に反映すること

成果物は直さない。設計と指示に反映する。

1. 応答時間切れは再試行をキューに入れるだけで、動いているランタイムを止めない。リース延長が有効な限り、生きているが詰まったワーカーでは応答時間切れ自体が起きない。ラッパーが type の規則から期限を持ち、期限でランタイムを止める。
2. ACP の `usage_update` はコンテキストの占有量と容量で、トークン数ではない。費用は ACP から取れないので、宣言の見積り値を使い、実測はベンダー側の記録を後で当てる。
3. 外向き通信の宛先制限は Docker のネットワークだけでは掛からない。ミニ PC で閉じている間は受け入れる。
4. Conductor の入力スキーマの強制は、登録が通ったことしか確認していない。合わない入力での挙動を e2e に加える。
5. 停止処理が SDK の多重プロセスのワーカー機構と噛み合わず、強制終了で回避している。次の抽選では SDK のワーカー機構を使わず、Conductor の poll と update の API を直接叩く単一プロセスのループにする。
6. 写しは 3 秒間隔で短い遷移を取りこぼし、終わった仕事の記録を捨てない。最終取得を終えた仕事の記録を捨てる。
7. 実 Codex と実 Claude の実行、jev の実 API、ミニ PC への配置は人の手順で、未実施。増分 2 の前に手順書に沿って行う。
