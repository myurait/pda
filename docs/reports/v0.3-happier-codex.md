## 4. Claude Code と Codex の起動のされ方

T2 の Claude は `tmux`（PID 131471）→ Happier wrapper（134111）→ Happier CLI（134128）→ `/home/user/.local/bin/claude`（134194）だった。Claude の引数には `--append-system-prompt`、`--mcp-config /tmp/happier-claude-mcp-config-…/…json`、`--plugin-dir …/state/tmp/hook-plugins/session-134128`、`--settings …/state/tmp/hooks/session-hook-134128.overlay.json`、`--permission-mode bypassPermissions` がある。標準の MCP bridge（134305）は Claude の子として起動した。これらのファイルは Happier が生成したもので、認証ファイルの内容は採録していない。

T4 は systemd user manager → Happier daemon（134063）→ `package-dist/index.mjs codex --happy-starting-mode remote --started-by daemon --permission-mode yolo …`（136495）→ `/home/user/.local/bin/codex app-server --listen unix:///tmp/happier-codex-m1Ex4T/private/app-server.sock …`（136526）だった。Codex の引数には Happier のセッション ID と MCP bridge 設定が `-c` で渡されていた。全引数は T6 の証拠にある。

Claude のログは T2 / T3 とも `stage=provider_launcher_entered {"runtime":"local"}`。画面には `This session is running locally on this computer. You can switch to remote to control it from the app.` と `Switch to remote` が表示された。導入済みコードでは local へのメッセージ受信や `abort` RPC が remote 切り替えへ進み、remote 分岐が `runtime: agent-sdk` の launcher を呼ぶ。指定の local を保つため、**画面のチャット入力・Switch to remote・abort RPC は試していない**。したがって「画面から入力しても local を維持できる」という実測結果は無い。停止に使ったのはセッション自体の `session stop` である。

[公式の Claude 実行方式の説明](https://docs.happier.dev/sessions/claude-unified-terminal)にある unified terminal への変更も行っていない。T9 の `ClaudeSdkAgentBackend` は製品内の query 実装であり、名前だけを根拠に `@anthropic-ai/claude-agent-sdk` と同一とは判定していない。ただし、指定された local launcher の経路にはならないことを導入済み成果物で確認した。

## 5. 認証

製品と実行器には `HOME=/home/user/v03/agent-home`、`CLAUDE_CONFIG_DIR=/home/user/pda/secrets/claude` を渡し、`PATH` の先頭を `/home/user/.local/bin` にした。手動起動は `env -u CODEX_HOME`、unit は `UnsetEnvironment=CODEX_HOME …` とし、daemon / Claude / Codex の実プロセスでも `CODEX_HOME` が未設定であることを確認した。既存の `.claude` / `.codex` symlink を利用した。信頼設定は各 CLI の画面で承認し、設定ファイルを手で編集していない。

Claude は既存の Claude Pro、Codex は既存の CLI ログインで動いた。`--auth native` を選び、API キーを入力せず、Connected Services へ認証を登録しなかった。これは [machine-local provider authentication](https://docs.happier.dev/agents/provider-authentication) の経路である。

Happier 自身には別のログインが要った。Web の `First time here — let's start` からローカルの試用アカウントを作成し、`happier auth login --no-open --method web` の接続先を同じブラウザで開き、`Accept Connection` を承認した（実際のログインは1回で成功）。この操作はモデル提供者の認証とは別で、API キーやメールアドレスの入力は無かった。

Happier 自身の認証は `/home/user/v03/happier/state/servers/env_36095987/access.key`（mode 600、500 bytes）、Web のログイン状態は `/home/user/v03/happier/browser-profile/` に保存された。値は読んだり報告へ写したりしていない。終了時の Happier `state/` 配下のメタデータ探索では、provider 用の `auth.json` / `.credentials.json` / `credentials.json` は見つからなかった。これは当該ディレクトリと名前に限った確認である。


既存の試用アカウントを開くため、保存済みプロファイルをそのまま使う起動スクリプトを残した。既存の同じプロファイルのブラウザが閉じている状態で、ミニ PC 上で実行する。

これは headless Chromium を起動し、ローカルの `127.0.0.1:9512` に DevTools の接続口を置く。ローカルでの再起動と認証・履歴の復元は確認済み。秘密の値を表示・書き出すスクリプトではない。開発 PC で次の転送を用意する（この端末間接続は未試験）。

```bash
ssh -N -L 9512:127.0.0.1:9512 user@<ミニPCのSSH接続先>
```

開発 PC の Chrome で `chrome://inspect/#devices` を開き、ネットワーク対象の Configure に `localhost:9512` を指定し、Happier ページの inspect を開くと保存済みブラウザを操作できる。通常の別ブラウザやスマホで同じアカウントへ入る際は、先にその端末の relay を公開 URL に合わせ、既存の画面の **Settings → Add your phone** と新端末の **Login / Restore account** でペアリングする。手動の **Restore with Secret Key Instead** もある。秘密鍵の保持元は上記ブラウザプロファイルで、CLI の `access.key` を Web の復元鍵として入力するものではない。[公式の端末追加・復元手順](https://docs.happier.dev/accounts/device-linking-and-restore)に従う。別端末への復元操作そのものはこの走行では未実施。
