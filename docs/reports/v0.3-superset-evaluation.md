## 結論

選別は終わっていない。CLI は入ったが、常駐するホストのサーバが、superset 自身のクラウドのアカウントへのログインが無いと起動しない。T2〜T9 は試せていない。

- 起動は 2 回とも「Error: Not logged in」「Hint: Run: superset auth login (or set SUPERSET_API_KEY)」で終わった。
- ログイン先は superset のクラウドである (CLI の既定の `SUPERSET_API_URL` は `https://api.superset.sh`、`packages/cli/src/lib/env.ts` の 11 行目)。公式文書も「The host server starts under your Superset session」と書く ([Host Server](https://docs.superset.sh/cli/host-server))。既存の Claude Code や Codex のログインで代える設定は、文書とソースに見つからなかった。
- アカウントを作るか、オーナーのアカウントでログインするかは、Codex にも設計側にもできない。オーナーが決める。
- ソースで確かめたこと: 端末の経路は、`claude --dangerously-skip-permissions` と `codex --dangerously-bypass-approvals-and-sandbox` を node-pty の端末で動かす。chat の画面は `@anthropic-ai/claude-agent-sdk` を使うので、H7 により使わない。製品の仕事の受け渡し (`agents create --from-terminal`) はある。
