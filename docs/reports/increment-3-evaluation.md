## 設計の見落とし（次の指示の範囲）

- ACP の `available_commands_update` と `session_info_update` が毎回 `unknown` の出来事になり、1 仕事に 4〜5 件の雑音を作る。Codex は状態と表題、Claude はコマンド一覧を送ってくる。次の指示では、この 2 種は出来事にしない（捨てる）と決める。表に無い出来事を作らない方針は変えない。
- 実 Codex の出力は「hello.py を作成し…」という文の後に JSON が続き、JSON として読めないので `result` の文として包まれた。Claude は JSON だけを返した。事前プロンプトが 3 行の仮置きなので、出力の形の指示が弱い。次の指示では、事前プロンプトに「出力は JSON だけ、前後に文を置かない」を足し、分類で末尾の JSON ブロックを取り出す 5 段目を足すかを決める。とりあえず前者だけにする。
- compose のプロジェクト名が `pda-increment-2` のまま。増分ごとに変える名前ではなかった。次の指示で `pda` に改め、既存ボリュームの引き継ぎ（`docker volume` の名前変更は無いので、名前付きボリュームを新プロジェクトへ複製する手順か、作り直しを受け入れるか）を手順書に書く。とりあえず作り直しを受け入れる。
- 実 Codex の終了処理の問題は、実機で初めて出た。試験用エージェントは npx を挟まないので再現しない。試験用エージェントを npx 経由で起動する経路を単体試験に足すかを次の指示で決める。とりあえず回帰試験（子プロセスを残すランチャー）で足りるとする。
