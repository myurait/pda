218: ## Agent allowlists
219:
220: Skill **location** (precedence) and skill **visibility** (which agent can use
221: it) are separate controls. Use allowlists to restrict which skills an agent sees,
222: regardless of where they are loaded from.
223:
224: ```json5
225: {
226:   agents: {
227:     defaults: {
228:       skills: ["github", "weather"], // shared baseline
229:     },
230:     entries: {
231:       writer: { default: true }, // inherits github, weather
232:       docs: { skills: ["docs-search"] }, // replaces defaults entirely
233:       "locked-down": { skills: [] }, // no skills
234:     },
235:   },
236: }
237: ```
238:
239: <AccordionGroup>
240:   <Accordion title="Allowlist rules">
241:     - Omit `agents.defaults.skills` to leave all skills unrestricted by default.
242:     - Omit `agents.entries.*.skills` to inherit `agents.defaults.skills`.
243:     - Set `agents.entries.*.skills: []` to expose no skills for that agent.
244:     - A non-empty `agents.entries.*.skills` list is the **final** set — it does not
245:       merge with defaults.
246:     - The effective allowlist applies across prompt building, slash-command
247:       discovery, sandbox sync, and skill snapshots.
