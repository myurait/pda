118: ### Permissions and scope
119:
120: Hook registration does not bypass plugin loading rules. The plugin must be
121: loaded and enabled; `plugins.enabled`, `plugins.allow`, and `plugins.deny` still
122: apply. Run `openclaw plugins reload <id>` after changing plugin code. With the default hybrid
123: reload mode, hook policy changes hot-reload the existing plugin runtime.
124:
125: - Non-bundled plugins need explicit
126:   `plugins.entries.<id>.hooks.allowConversationAccess: true` for
127:   `before_model_resolve`, `agent_turn_prepare`, `before_prompt_build`,
128:   `before_agent_reply`, `llm_input`, `llm_output`, `before_agent_finalize`,
129:   `agent_end`, and `before_agent_run`. Bundled plugins are allowed unless this
130:   option is explicitly `false`.
131: - `allowPromptInjection: false` blocks `agent_turn_prepare`,
132:   `before_prompt_build`, `heartbeat_prompt_contribution`, and durable next-turn
133:   injections. It defaults to allowed, but does not grant conversation access.
134:   The first two hooks therefore need both permissions.
135: - These are specific registration gates, not a sandbox or a universal filter
136:   for every hook that can see message data. Install only plugins you trust.
137:
138: Incognito sessions do not dispatch `llm_input` or `llm_output` observations.
139: Their `agent_end` hooks still receive run identity, success, and duration for
140: cleanup and settlement, but receive empty `messages` and no `error` text.
141: Policy, provider, approval, and explicitly invoked tool hooks remain active.
142: This boundary does not sandbox plugins or disable native harness telemetry.
143:
144: A typed handler receives `(event, ctx)`. The event describes the operation;
145: the second argument carries hook-specific context. Fields such as
146: `ctx.agentId`, `ctx.sessionKey`, and `ctx.runId` are optional on many hooks and
147: may be absent for the emitting path. A registration is not automatically
148: scoped to one agent or session: check the context in your handler when needed.
149:
150: Read your plugin's resolved settings from `api.pluginConfig` inside the
151: registration closure. Typed hooks do not receive a universal
152: `event.context.pluginConfig` field; that field belongs to the internal
153: `api.registerHook(...)` event contract.
154: By default in hybrid reload mode, editing `plugins.entries.<id>.config` replaces the
155: plugin instance and reruns registration with the new settings.
