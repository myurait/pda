## 3. 試用の結果

## 4. Claude Code と Codex の起動のされ方

T2 の親子関係は `systemd --user (1274)` → `start.sh (290272)` → `herdr server (290273)` → `/bin/bash (290300)` → `/home/user/.local/bin/claude --permission-mode acceptEdits (291021)` だった。起動時には `DISABLE_AUTOUPDATER=1` も付けた。

T4 は同じ Herdr → `/bin/bash (290429)` → `/home/user/.local/bin/codex --dangerously-bypass-approvals-and-sandbox (291888)` だった。Collie `_exec-bridge (290325)` は `start.sh` の子だった。

実際に使用した経路は Herdr の PTY に CLI コマンドを入力するもの。固定版 Herdr の [src/pane.rs:1979–2007](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/pane.rs#L1979) はシェル用の `CommandBuilder` を作り、[src/pty/backend/unix.rs:12–35](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/pty/backend/unix.rs#L12) は PTY を開いてそのコマンドを spawn する。Collie の [bridge/mux/herdr/client.ts:619–631](https://github.com/AltanS/collie/blob/0890f72e7d858e25f3a886a96a839350b2fd346b/bridge/mux/herdr/client.ts#L619) は Herdr socket の `pane.send_text` / `pane.send_keys` / `pane.close` に操作を渡す。この経路に Claude Agent SDK や ACP adapter は使用していない。

引き継ぎの入口は Herdr の [src/cli/agent.rs:777–854](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/cli/agent.rs#L777)。`agent prompt` を socket の `agent.prompt` に渡す。Collie API で必要なキー名は [bridge/mux/keys.ts:39 以降](https://github.com/AltanS/collie/blob/0890f72e7d858e25f3a886a96a839350b2fd346b/bridge/mux/keys.ts#L39) の `Escape` で、Herdr CLI の help にある `esc` と混同した。

## 5. 認証

unit と手動起動用 `env-run` で `HOME=/home/user/v03/agent-home`、`CLAUDE_CONFIG_DIR=/home/user/pda/secrets/claude` を渡した。`CODEX_HOME` は unit に記載せず、手動では `env -u CODEX_HOME` で除いた。PATH の先頭は `/home/user/.local/bin`。実行中の Herdr、Collie、両 CLI の対象環境変数だけを取得し、`CODEX_HOME=<unset>` を確認した（`08-auth-environment.txt`）。Codex が起こした code-mode-host は自分の補助実行ファイル用パスをさらに前に追加していた。

用意済みの `.claude` / `.codex` symlink を使用し、認証ファイルの内容は読んでいない。別の認証複製を作成する操作、API キー入力、追加のログインはしていない。Claude は Claude Pro と表示され、両 CLI が依頼を処理した。Collie の transcript ファイル参照は `COLLIE_TRANSCRIPT=off` とし、PTY の出力を観測した。試用の loopback 接続ではペアリングも設定していない。

Herdr/Collie の MCP、hook、plugin、skill の追加登録は実施していない。`herdr server` と `collie _exec-bridge` を直接起動した。製品による新しい認証ファイルは、製品用ディレクトリと agent-home の symlink を辿らないメタデータ確認では見つからなかった。

終了時は `systemctl --user stop v03-herdr-collie.service` で全子プロセスを停止した。試用中に Claude CLI が作った `/home/user/pda/secrets/claude/backups/.claude.json.backup.*` の 5 ファイルをメタデータのみ記録して削除し、今回の scratch 用に新規作成された Claude CLI cache directory と Python cache を削除した。削除対象の全パス・確認結果は `10-cleanup.txt`。認証本体、`settings.json`、`config.toml` は手で変更・削除していない。信頼設定は CLI が記録したまま保持し、以前からあった他製品のファイルには触れていない。製品のバイナリ、設定、unit、製品専用の状態は保持した。

## 6. 人の手順

今回の導入・試用に root を要する手順はなかった。外から開く際は次の手順になる。

1. `/home/user/v03/herdr-collie/config/collie/.env` に、公開に使用するノードの正確な DNS 名を `COLLIE_PUBLIC_HOSTS=<ノード名>.<tailnet>.ts.net` として設定する。今回の起動ログでは非 loopback の Host が未許可なので、この設定が必要。個人の Tailscale ログインでアクセスを制限する場合は `COLLIE_TRUSTED_USER=<Tailscale のログイン名>` も設定する。これらは値を確認して人が設定するもので、本走行では追加していない。
2. `systemctl --user start v03-herdr-collie.service` で起動する。既に起動済みのとき設定を変えた場合は restart する。
3. 次を実行する。本走行では実行していない。

   ```bash
   /home/user/.local/bin/tailscale-pda serve --bg --https=19117 http://127.0.0.1:5117
   ```

4. 同じ tailnet から `https://<ノード名>.<tailnet>.ts.net:19117/` を開く。ローカル・SSH 転送先の URL は `http://127.0.0.1:5117/`。実際の SSH 転送確認は設計側の作業。
5. Collie 自体に通常のアカウントログイン画面はない。端末の書き込み資格をペアリングで設定する場合は、次のコマンドをホストで実行し、表示されたコードを画面の **Settings → Paired devices** に入力する。コードの値は証拠に残さない。

   ```bash
   cd /home/user/v03/work/herdr-collie/scratch
   /home/user/v03/herdr-collie/env-run \
     /home/user/v03/herdr-collie/release/collie-1.16.1-linux-x64/bin/collie pair
   ```

   ペアリングのハッシュ等は今回の構成では `/home/user/v03/herdr-collie/state/collie/` に保存される。公式 security 文書では、1 台以上が登録されている間は書き込みに端末トークンが必要になる。今回この手順は実施していない。

## 7. 分からなかったこと

- Claude の初回 `Ctrl+C` が中断に至らなかった原因。正しい Collie キー名 `Escape`、画面のキー操作を使用したときの両 CLI の停止可否・所要秒数。再試行上限のため追加検証していない。
- Codex の `/new` 直後の入力欠落について、会話切り替えとキー入力のどの段階で欠落したか。記録したのは送信本文と画面に残った本文の相違。
- Herdr の `--wait` が `done` を返したあとも受け手の作業が続いた理由。状態を報告する追加 hook は入れていない。
- Tailscale Serve・開発 PC・スマートフォンからの実到達、再起動後の復元、任意の端末ペアリングは今回の確認対象に含めていない。
