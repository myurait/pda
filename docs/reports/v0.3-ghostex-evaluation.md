## 結論

T1〜T5 と T9 は通った。必須の条件のうち、R1、R2、R7、R13 をミニ PC の上で確かめた。R4 は、常駐と API の応答までは確かめたが、ブラウザの画面が描けなかった。

- 構成: 公式の `gxserver` (API、`127.0.0.1:58744`) と、`ghostex web` (画面、`127.0.0.1:5118`) を 1 つの user unit で起こした。ブラウザの画面は配布物に入っておらず、公式の手順で Rust、Zig、wasm-bindgen、Bun を利用者の権限で入れて作った。
- T2、T4: Ghostex 自前の zmx の端末の中で、`claude` と `codex --no-daemon` の実行ファイルがそのまま動き (`server/src/agents/launch_plan.rs`)、途中の出力が製品の端末の WebSocket で届いた。tmux は使っていない。
- T3、T5: 製品の `interrupt-session-chat` で、Claude は 0.383 秒、Codex は 0.052 秒で止まった状態になった。プロセスは残り、次の依頼を待つ状態に戻った。
- T9: 製品の `ghostex agents send` で、Codex から Claude Code へ、Claude Code から Codex へ仕事を渡せ、受け手の途中の出力が届いた。Codex から送る側は、Codex のサンドボックスが gxserver への接続を止め、そのセッションだけ Full Access にして通った。
- T8: ミニ PC の上の headless の Chromium で画面を開いたが、2 回とも WebGPU の装置が失われて描画が止まり、黒い画面だった。画面は WebGPU を使う作りで、GPU の無いこのマシンの headless の Chromium では描けない。手元の PC やスマホのブラウザで描けるかは確かめていない。
