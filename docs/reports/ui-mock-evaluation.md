## オーナーの所見

- 配色だけを Datadog に寄せ、暗い配色を勝手に選んでいる。構成を読む画面なので暗い配色は見づらい
- UX/UI を解釈して分解しておらず、段落と要素を並べた HTML になっている。画面の一覧、動線、視点の誘導が設計されていない
- タスクのページは分割と合流の流れを見せる画面なのに、素の HTML で組んでいる。Step Functions のような図で見せる必要があり、専用のライブラリが要る
- 「指示の履歴」の区画がフローと結び付いていない。指示がセルなら、この区画は生まれない
- 報告を平文で出している。Markdown か HTML を整形しないと長い報告が読めない
- 実行器が複数のセルを同時に担うことを前提にしていない
- 入力待ちの画面は、文脈と報告なしに問いへ答えさせており、成り立たない

## 原因（指示の側）

所見の多くは、実装ではなく指示から生じている。

- システムが何のためにあるかを伝えず、要件正本を語彙の出典として読ませただけだった
- ユースケースと動線を書かず、画面ごとに「見せるもの」と「できること」を並べた。要素の羅列はこの形をそのまま写した結果である
- 「指示の履歴」を見せるものとして指示に書いた。要件の側にも「タスクは指示の列と実行の列から成る」と書いており、指示をセルとする考えと矛盾していた
- 外部の部品とビルド工程を禁じたため、図の部品を使えなかった
- 「明暗の差がはっきりした」とだけ書き、明るい配色と定めなかった
- 報告の整形、実行器が複数のセルを担うこと、問いを文脈と一緒に見せることを書かなかった

要件正本は同じ日に改めた（指示をフロー上のセルとする、実行器が複数のセルを同時に担う、フローを図で見せる、報告を整形する、問いを文脈と一緒に見せる。受け入れ条件 A27〜A30）。
