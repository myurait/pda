## 行う確認

### R3-0 3 つのエージェントを作る

- 製品の公式の手順 (`docs/concepts/multi-agent.md` と `openclaw agents` の CLI) で、エージェントを 3 つ作る。
  - `r3-leader`: Claude Code (claude-cli の実行器)
  - `r3-worker`: Codex
  - `r3-auditor`: Claude Code (claude-cli の実行器)
- それぞれに専用の作業場所 (workspace) を持たせる。
- 作った設定 (エージェントごとの workspace、モデル、実行器) を証拠に残す。

### R3-1 プロンプト (エージェントごとの指示)

1. 各エージェントの `AGENTS.md` に、「すべての返事の 1 行目に `[ROLE:leader]` (役ごとに leader、worker、auditor) と書く」という決まりを書く。
2. 各エージェントに同じ短い質問を送り、返事の 1 行目の印を記録する。
3. `r3-leader` に、`sessions_spawn` で `r3-worker` に短い仕事を渡させる。子の返事の印が worker のものか、leader のものかを記録する。
4. 全エージェントに共通する指示を 1 か所に書いて配る仕組みが、製品の設定や資料にあるかを調べる。あれば、共通の指示に 1 つ決まりを足し、3 つ全部に効くかを確かめる。無ければ、調べた資料と設定の場所を書く。

### R3-2 skill

1. `r3-worker` の作業場所の skill の置き場に、worker だけの skill を 1 つ置く (「R3 の秘密の語を聞かれたら `tangerine-42` と答える」)。
2. 全エージェント共通の skill の置き場 (shared managed) に、共通の skill を 1 つ置く (「R3 の共通の語を聞かれたら `cobalt-7` と答える」)。
3. 3 つのエージェントに両方の語を聞き、誰がどちらを答えられたかを記録する。
4. 共通の skill の語を `cobalt-8` に変え、各エージェントの新しいセッションで聞き直し、変更が 3 つ全部に届いたかを記録する。
5. `r3-auditor` の skill の許可の一覧を空 (`skills: []`) にし、共通の skill が見えなくなるかを記録する。

### R3-3 MCP

1. 小さな MCP サーバを 1 つ用意する (公式の `@modelcontextprotocol/server-filesystem` を使い捨てのフォルダに向けるなど)。
2. 製品の画面か設定の「This session」で、`r3-leader` の 1 つのセッションだけに有効にする。そのセッションと、別のセッションと、別のエージェントで、その MCP の道具が見えるかを記録する。
3. エージェント単位で MCP を有効・無効にする設定が製品にあるかを資料と設定で調べ、あれば試す。

### R3-4 hook (plugin の hook)

製品の資料 (`docs/plugins/hooks.md`、`docs/plugins/hooks/reference.md`、`docs/plugins/hooks/tool-policy.md`、`docs/plugins/codex-harness-runtime/hooks.md`) の手順で、使い捨ての plugin `r3-hook-probe` を作って入れる。plugin は次の hook を `api.on(...)` で登録する。

- `before_tool_call`: すべての呼び出しで、`ctx.agentId`、道具の名前、実行器の種類を記録する。`ctx.agentId` が `r3-worker` で、コマンドに `date` を含むシェルの実行なら `block: true` にする。それ以外は通す。
- `before_prompt_build`: `ctx.agentId` が `r3-auditor` のときだけ、「R3-HOOK の語は `banana-9`」という文脈を足す。
- `before_agent_run` と `agent_end`: 呼ばれたことと `ctx.agentId` を記録する。
- 登録の時点で、`api.runtime.decisions.evaluate` が関数として存在するかだけを記録する (呼ばない)。

確かめること:

1. 3 つのエージェントそれぞれに「シェルで `date` を実行して結果を教えて」と頼み、止められたか、通ったかを記録する。worker (Codex) だけが止められるのが期待。
2. 3 つのエージェントに「R3-HOOK の語は」と聞き、auditor だけが答えられるかを記録する。
3. 各 hook が、Claude Code の実行器と Codex の実行器のそれぞれで呼ばれたか (記録が残ったか) を表にする。Claude Code と Codex の内蔵の道具 (Bash、Edit、Codex のシェルなど) の呼び出しが `before_tool_call` に届くかも記録する。
4. `openclaw models list` などで、判定モデル (decisionModel) の役と `decision_evaluate` の道具が、入っている版にあるかを記録する。TypeSafe の plugin は入れない。API キーは使わない。

## 終わり方 (共通の指示との違い)

- 3 つのエージェントと、その `AGENTS.md` は残す (オーナーが画面で見られるようにする)。
- `r3-hook-probe` の plugin は無効にして外す。R3-3 の MCP の設定、R3-2 の skill は消す。消したものを報告に書く。
- `v03-openclaw.service` と `v03-cccc.service` は動かしたままにする。
- 共通の指示どおり、製品が CLI の共有の設定に足した登録や `.bak` があれば消して記録する (認証の本体、`settings.json`、`config.toml` は消さない)。
