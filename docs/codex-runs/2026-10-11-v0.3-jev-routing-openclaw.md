共通の指示 `docs/codex-runs/2026-09-28-v0.3-setup-common.md` と、製品ごとの指示 `docs/codex-runs/2026-09-28-v0.3-setup-openclaw.md` を最初に読み、それに従う。この走行は、OpenClaw の plugin の hook から判定モデル Jev を呼び、統率役から作業者か監査役への仕事の割り当てを Jev に決めさせ、その割り当てを hook で守らせることができるかを確かめる。あわせて、前の走行で残った 2 点を確かめ直す。共通の指示と違う点は次のとおり。

## 行う確認

### J-0 TypeSafe の plugin を入れる

1. 製品の公式の手順 (`docs/plugins/typesafe.md`) で `@openclaw/typesafe` を入れて有効にする。
2. plugin の設定の `apiKey` を、保管庫の参照 `{ source: "store", provider: "default", id: "TYPESAFE_API_KEY" }` にする。
3. `r3-leader` にだけ `decisionModel: "typesafe/jev-latest"` を設定する。`r3-worker` と `r3-auditor` には設定しない。
4. `r3-leader` にだけ `decision_evaluate` の道具が付くことを確かめる。
5. 製品の CLI に判定を試すコマンドがあればそれで、無ければ `r3-leader` に `decision_evaluate` を 1 回呼ばせて、boolean の簡単な質問で 1 回判定させる。結果と所要時間を記録する。

### J-1 統率役が作業者の結果を受け取れるか (確かめ直し)

1. `r3-leader` に「`r3-worker` に `sessions_spawn` で『3+4 はいくつか』を渡し、完了の通知を待ってから、子の答えをそのまま引用して報告して」と頼む。
2. 統率役の最終の返事に、子の答えが引用されたかを記録する。
3. 前の走行と同じ `Gateway client authority closed` の誤りが出たら、誤りの全文と、そのときの OpenClaw の journal を記録し、もう 1 回だけやり直す。原因を製品の資料とソースで調べ、分かった範囲を書く。

### J-2 Jev で割り当てを決め、hook で守らせる

製品の資料 (`docs/plugins/hooks.md`、`docs/plugins/hooks/reference.md`、`docs/plugins/hooks/tool-policy.md`、`docs/plugins/hooks/prompt-and-session.md`、`docs/concepts/decision-models.md`) に従い、使い捨ての plugin `jev-router-probe` を作って入れる。前の走行の `r3-hook-probe` (証拠の `r3-4-plugin-index.ts.txt`) を下敷きにしてよい。

- `before_prompt_build` (`ctx.agentId` が `r3-leader` のときだけ):
  - 今回の依頼の文 (`currentUserMessage`。無ければ `prompt`) を state にし、`api.runtime.decisions.evaluate` で choice の質問を 1 つ判定させる。選択肢は次の 2 つ。
    - `worker`: コードを書く・直す、コマンドを実行する、調べる作業
    - `auditor`: 文章の分かりやすさや、決まりへの合い方を確かめる作業
  - `purpose` は `pda.route`、`rubricVersion` は `1`、`agentId` は `r3-leader` を渡す。
  - 判定の結果 (選ばれた選択肢、確率、所要時間、`unavailable` ならその理由) を記録し、セッションごとに覚えておく。
  - 「この依頼は Jev の判定で <選ばれた選択肢> に渡す。`sessions_spawn` の `agentId` は `r3-<選ばれた選択肢>` を使う」という文脈を足す。
  - 判定が `unavailable` のときは、文脈を足さずに通常どおり進め、そのことを記録する。
- `before_tool_call` (`ctx.agentId` が `r3-leader` で、道具が `sessions_spawn` のとき):
  - 引数の `agentId` が、そのセッションで Jev が選んだ相手と違えば `block: true` にし、理由に Jev の判定を書く。同じなら通す。判定が無いセッションでは通す。
  - 呼ばれたことと、止めたか通したかを記録する。

確かめること (各 1 回):

1. コードの依頼: `r3-leader` に「scratch の `hello.py` に、名前を受け取って挨拶を返す関数を足す作業を、適切な役に渡して」と頼む。Jev の判定、足された文脈、`sessions_spawn` の相手、止めたか通したか、子の結果を記録する。
2. 文章の依頼: `r3-leader` に「次の説明文が分かりやすいかを、適切な役に確かめさせて: 『本機能は、所定の条件下において、所要の処理を適宜実施するものである。』」と頼む。同じものを記録する。
3. 守らせる確認: `r3-leader` に、2 と同じ文章の依頼を「必ず `r3-worker` に渡して」と付けて頼む。hook が `r3-worker` への委譲を止めるか、そのあと統率役が `r3-auditor` に渡し直すかを記録する。
4. 各 hook と各判定の所要時間を表にする。hook の時間切れが起きたかも記録する。

### J-3 「This session」で MCP を有効にする (確かめ直し)

前の走行の R3-3 と同じ小さな MCP サーバを、最初から正しい node のパス (`/home/user/.local/bin/node`) で用意する。共通の定義を無効にしたまま、`r3-leader` の 1 つのセッションにだけ有効にする設定を入れ、そのセッションと、別のセッションと、別のエージェントで、道具が見えるか、呼べるかを記録する。

## 終わり方 (共通の指示との違い)
