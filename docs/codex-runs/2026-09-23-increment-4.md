### 2.4 判定器を実 jev に繋ぐ

`JEV_MODE` は `fixture` と `live`。`live` の API 呼び出し（送信先、認証、本文、answers の読み取り）は既に実装されている。次を足す。

- 実行器の可用性。判定器のラッパーは、Conductor のポーリング記録から直近 60 秒以内にポーリングしたワーカーを可用とみなし、state に `available_executors`（実行器 ID の一覧、宣言ファイル名の順）を足す。ポーリング記録はとりあえず `GET /api/tasks/queue/polldata/all` で取る（各要素に `queueName`、`workerId`、`lastPollTime` がある想定。`queueName` はタスク名 `{type}.{executor}`）。この経路が 404 か形が違えば、宣言した全タスク名について `GET /api/tasks/queue/polldata?taskType={name}` を呼ぶ形に切り替え、どちらで動いたかを報告書に書く。fixture でも同じ規則を通す
- 置き換え。jev（または fixture）が選んだ実行器が可用でない、またはその type を支えない場合、その type を支える可用な実行器のうち宣言ファイル名の順で先頭のものに置き換え、`judge.answer` に `pda.question_id: executor`、`pda.answer: substituted:<元>-><先>` を記録する。候補が無ければ `then: finish` にし、`judge.answer` に `pda.question_id: next_type`、`pda.answer: finish:no_available_executor` を記録する。既存の `judge_selected_unsupported_pair` の失敗は、この置き換えの後にも残る場合（起こり得ない組が渡された場合）だけに残す
- 繰り返しの上限の上書き。環境変数 `PDA_MAX_ROUNDS` があれば正本の `limits.max_rounds` より優先する。試験用。compose の `exec-jev` に `PDA_MAX_ROUNDS: ${PDA_MAX_ROUNDS:-}` を通す
- `tools/judge_probe.py`。引数 `--job-id <id>`（Conductor から `GET /api/workflow/{id}?includeTasks=true` で取る）か `--workflow-file <path>`（証拠の抜粋の JSON）と、`--initial-input <text>`（省略時はワークフロー入力の `initial_input`）、`--conductor`、`--registry`。判定器のラッパーと同じ関数で state を組み立て（可用性の欄は Conductor から取れるときだけ）、実 jev に送り、`{"state_summary": {"rounds": n, "previous_outputs": k, "available_executors": [...]}, "answers": {...}, "elapsed_ms": n}` を標準出力に JSON で出す。閾値の適用や合否の判定はしない。API キーは環境変数 `TYPESAFE_API_KEY`、無ければ `secrets/typesafe_credentials`。state を組み立てる関数は `src/pda_wrapper/drivers/jev.py` から呼ぶ（複製しない）

### 2.5 可視化の最初の画面（`src/pda_view/`）

`python -m pda_view` で起動する読み取り専用の HTTP サーバ。Python の標準ライブラリ `http.server`（`ThreadingHTTPServer`）と `httpx` だけを使う。フレームワーク、テンプレートエンジン、ビルド工程、npm を使わない。

環境変数: `CONDUCTOR_URL`、`OPENOBSERVE_URL`（`http://openobserve:5080`）、`ZO_ROOT_USER_EMAIL`、`ZO_ROOT_USER_PASSWORD`、`OPENOBSERVE_STREAM`（既定 `pda_events`）、`PDA_VIEW_PORT`（既定 5081）。

API（すべて JSON、Conductor と OpenObserve へは要求ごとに問い合わせ、保存しない）。

- `GET /api/jobs`: 実行中（`GET /api/workflow/running/pda_job`）と最近終わった仕事（`GET /api/workflow/search?query=workflowType='pda_job'&sort=startTime:DESC&size=50`。索引は Elasticsearch。この `query` の書き方でエラーになれば `query=workflowType IN (pda_job)` に切り替え、どちらで動いたかを報告書に書く）。各要素は `job_id`、`status`、`start_time`、`end_time`、`executors`（セルの `taskDefName` から取った実行器 ID の一覧）、`initial_input`（先頭 80 字）
- `GET /api/jobs/{id}`: ワークフローの記録から `job_id`、`status`、`reason`、`initial_input`、`cells`。`cells` は参照名が `c` か `judge` で始まるタスクを `seq` の順に並べ、各要素に `ref`、`type`、`executor`、`status`、`retry_count`、`start_time`、`end_time`、`duration_ms`、`reason`、`output_kind`、`output_excerpt`（payload の JSON 文字列の先頭 200 字）
- `GET /api/jobs/{id}/events?cell=<ref>`: OpenObserve の検索 API に `SELECT * FROM "<stream>" WHERE pda_job_id = '<id>' ORDER BY _timestamp ASC LIMIT 1000` を送り（`cell` があれば `AND pda_cell_id = '<ref>'`）、各行を `time`、`kind`、`executor`、`cell`、`summary` に写す。`summary` は種別ごとに要点 1 つ（tool.call は title、command.run はコマンドと終了コード、judge.answer は問いと答え、output.classified は kind、engine.task は状態、turn.end は stop_reason、それ以外は空）
- `GET /`: 画面の HTML。`GET /static/app.js`、`GET /static/app.css`: ファイルはパッケージ内に置き、そのまま返す

画面（1 枚の HTML、素の JavaScript、日本語）。

- 上部に仕事の一覧。行を選ぶと下に詳細。詳細はセルの表と出来事の時間軸。セルの行を選ぶと出来事をそのセルに絞り、もう一度選ぶと解除
- 3 秒ごとに一覧と表示中の詳細を取り直す
- スマートフォンの幅（375px）で横スクロールが出ない。文字は 14px 以上。表は幅が足りないときは折り返す。色は状態（COMPLETED、FAILED、IN_PROGRESS、SCHEDULED、TIMED_OUT）で分ける
- 外部の CDN やフォントを読み込まない

compose のサービス `pda-view`。イメージは `pda-executor:local`（同じ Dockerfile。`PDA_MODULE=pda_view`）。ポート 5081 を公開。ネットワークは `public`、`telemetry`、`mirror`（Conductor と OpenObserve に到達するため。`mirror` は Conductor 専用の内部ネットワークなので、写しと同居する）。非 root。OpenObserve の認証は `deploy/.env` の値を compose が環境変数で渡す。

### 2.6 試験

単体試験は 2.1〜2.5 の各項目に対応するものを足す。可視化は、Conductor と OpenObserve を httpx のモックにして 3 つの API の形を確かめる。`available_executors` の計算と置き換えの規則はモックの polldata で確かめる。

e2e の共通規則: fixture で特定の実行器を名指しする仕事（4、5、6、9、10、11）を開始する前に、ポーリング記録にその実行器の 60 秒以内のポーリングが現れるまで待つ（可用性の規則で置き換えられないため）。`GET /api/jobs` の終わった仕事の一覧は Elasticsearch の索引が数秒遅れるので、直後に断定せず待って確かめる。

e2e は増分 3 の 1〜12 を新しいプロジェクト名とタグに合わせて直し（10〜12 は費用が掛かるので、今回は 1〜9 と 13〜14 を実行し、10〜12 は実行しない。報告書にそう書く）、次を足す。

13. 実 jev。`secrets/typesafe_credentials` がある。費用の上限は、実 jev の呼び出しが最大 3 回（判定器 2 回と道具 1 回）、実行器のセルが最大 6（2 回 × cell_count 3、再試行なし）。`JEV_MODE=live`、`PDA_MAX_ROUNDS=2` で `exec-jev` を再作成し、profile `real` の `exec-codex-personal` と `exec-claude-personal` を起動する（費用が掛かるので、全 type の定義の `retryCount` を試験中だけ 0 にし、終了時に戻す）。`initial_input` は「作業ディレクトリに hello.py を作り、実行すると hello と表示するようにせよ。作ったファイル名を報告せよ」で仕事を 1 つ開始する。確かめるのは、判定器が `flow` の出力を返しスキーマを通ること、`judge.answer` に 4 問の実際の答えと確信度が残ること、可用性による置き換えが起きた場合はその記録が残ること、仕事が上限 2 回以内で `COMPLETED` か `FAILED` のどちらかで終わること（どの実行器が選ばれ、どの type が走ったかは制御せず、記録する）。証拠に、判定器の入力 state の要約（可用な実行器の一覧、前の回の出力の数）、4 問の答え、選ばれたセル、最終状態を残す。終わったら `JEV_MODE=fixture`、`PDA_MAX_ROUNDS` 無し、`retryCount` を元に戻し、real の実行器を止める
14. 可視化。`GET /api/jobs` に e2e 1 の仕事が含まれ、`GET /api/jobs/{id}` のセルが Conductor の記録と一致し（参照名の並びと状態）、`GET /api/jobs/{id}/events` が e2e 2 で確かめた出来事の件数以上を返し、`cell=judge__1` で絞ると `pda_cell_id` が `judge__1` の行だけになる。`GET /` が 200 で `<html` を含み、`/static/app.js` と `/static/app.css` が 200。ホストの 5081 番に到達できる

`tools/judge_probe.py` は e2e 13 の仕事の job_id で 1 回実行し、出力を証拠に保存する（実 jev をもう 1 回呼ぶ。これも費用に含める）。

## 3. 部品ごとの受け入れ条件

報告書に、次の条件を 1 つずつ合否で書く。確かめ方も書く。

- ACP の通知の整理: 2 種の通知が出来事にならず、他の未知は `unknown`
- 事前プロンプト: 6 ファイルに追記がある。実 jev の e2e で動いた実行器の出力が JSON として読めたかを記録する（読めなかった場合も不合格にはせず、事実として書く）
- compose: プロジェクト名 `pda`、タグ `local`、旧プロジェクトのコンテナとボリュームが無い
- 可用性: polldata から 60 秒以内のワーカーを可用とする。fixture の e2e でも state に `available_executors` が入る（fake-a、fake-b、tools、jev の 4 つ）
- 置き換え: 単体試験で、可用でない実行器を選んだ答えが置き換えられ、記録が残る。候補が無いと finish になる
- 上限の上書き: `PDA_MAX_ROUNDS=1` で 1 回で finish
- 判定器の道具: `--workflow-file` で証拠の抜粋を読み、`--job-id` で Conductor から読み、いずれも実 jev に送って JSON を出す（e2e 13 の後に 1 回）
- 可視化の API: 3 つの API が指示の欄を返す。Conductor と OpenObserve が落ちているときは 502 と理由の JSON を返し、プロセスは落ちない
- 可視化の画面: `/` と静的ファイルが返る。画面の HTML に一覧、詳細、時間軸の要素がある
- 増分 3 の全部品: 受け入れ条件を満たしたまま（e2e 1〜9）
- 手順書: `pda-view` の開き方、Tailscale の Serve で 5081 番を tailnet に公開する手順（`tailscale-pda serve` の使い方は `~/.local/bin/tailscale-pda serve --help` を読んで確かめ、実行はしない）、実 jev への切り替え手順、判定器の道具の使い方、旧プロジェクトの削除手順
