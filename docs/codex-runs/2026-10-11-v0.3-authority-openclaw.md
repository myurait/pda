# v0.3 OpenClaw: 子の結果を受け取る段の誤りの確認

この走行は、統率役 (`r3-leader`) が `sessions_spawn` で起こした作業者 (`r3-worker`) の子の結果を受け取る段で出る `Gateway client authority closed before dispatching ...` の誤りが、画面を開いたまま普通に使ったときにも出るかを確かめる。前回までの試験では、採取のクライアントが接続ごとにメモリの中で device identity を作り直していた。画面 (Control UI) は、ブラウザに保存した 1 つの device identity で接続し、走行の間つないだままにする。

## 読むもの

- 共通の指示 `docs/codex-runs/2026-09-28-v0.3-setup-common.md` の 2 節 (秘密情報、認証、資源の決まり) と、やり直しの上限。試用の T1〜T9 は行わない。
- 報告 `docs/reports/v0.3-openclaw-codex.md` の 9 節と 10 節。共通の指示 1 の「他の製品の報告を読まない」の例外。
- 前回の採取のコード `docs/reports/evidence/v0.3-openclaw/2026-10-11-jev/j-0-collector-sources.txt`。接続のしかたはこれを土台にしてよい。

## 行う試し

依頼の文は全部の試しで同じにする: `r3-worker に sessions_spawn で「7 と 8 を足した答えだけを 1 行で返して」と頼み、子の完了の通知を待ってから、子の答えをそのまま引用して私に報告して。`。試しごとに `r3-leader` の新しいセッションを使う。

- A (画面と同じ使い方、3 回): device identity を 1 つ作ってファイルに保存し、試し A の 3 回とも同じ identity を使う。1 回ごとに 1 本の接続を開き、依頼を送ってから統率役の最後の返事が届くまで (上限 5 分) 接続を閉じない。
- B (途中で接続を切る、1 回): A と同じ identity で接続して依頼を送り、統率役の `sessions_spawn` を観測したら接続を閉じる。2 分待ってから同じ identity でつなぎ直し、そのセッションの記録を読む。
- C (別の identity でつなぎ直す、1 回): B と同じ。ただし、つなぎ直すときにメモリの中で新しい identity を作る。

各試しで記録すること:

- 統率役が子の答えを引用できたか。引用までの時刻。
- 返事、出来事、セッションの記録に出た誤りの文 (`Gateway client authority closed`、`Gateway caller authority is no longer active`、`Subagent terminal signal owner changed before commit` を含む)。
- Gateway の journal とログファイル (`/tmp/openclaw/openclaw-2026-10-11.log`) の、その試しの時間帯の該当の行。
- 誤りが出たときに、その誤りを出した処理 (RPC の名前) と、どの接続の権限が閉じたと判定されたか。

結果を見てから、出る条件についての結論を書く。A で出なければ「画面を開いたまま使う形では出なかった (3 回)」、B か C で出れば、出る条件を書く。A でも出た場合は、その試しの journal から分かることを書き、原因が分からなければ分からないと書く。
