# v0.3 候補のセットアップ: orca

共通の指示 `docs/codex-runs/2026-09-28-v0.3-setup-common.md` を最初に読み、それに従う。この製品について決まっていることは次のとおり。

- 製品: https://github.com/stablyai/orca
- 公式文書: https://www.onorca.dev/docs 。リポジトリの `docs/reference/headless-linux-server.md` と `docs/site/content/docs/` の `remote-servers.mdx`、`cli/orchestration.mdx`、`agents/hooks-memory.mdx` を読む。
- 名前 (ブランチ、ディレクトリ、unit、報告書、証拠に使う `<製品>`): `orca`
- ブランチ: `v0.3/setup-orca`
- 待ち受けのポート: 5113
- Tailscale Serve の番号 (報告書の「人の手順」に書くもの): 19113
- 版: release `v1.4.218` の `orca-linux.AppImage`。

## 導入

- このマシンには Xvfb と、Electron が使う主なライブラリ (libgtk-3、libnss3、libgbm、libasound) が入っている。libfuse2 は無い。
- AppImage を `~/v03/orca/` に置き、利用者の権限で `--appimage-extract` して、`~/v03/orca/squashfs-root/AppRun serve` で動かす。公式の手引きにある sudo、`/opt/orca`、専用の利用者を作る手順は使わない。
- 起動の引数は `serve --port 5113 --pairing-address 100.69.167.33 --json`。`100.69.167.33` はこのマシンの Tailscale の IPv4。
- unit の環境に、共通の指示 2.3 の 3 つと `PATH` のほかに、`LIBGL_ALWAYS_SOFTWARE=1`、`ORCA_TELEMETRY_DISABLED=1`、`DO_NOT_TRACK=1` を入れる。`DISPLAY` は入れない (Orca が自分で Xvfb を起こす)。`KillMode=mixed` にする。
- `orca serve` は全インターフェースで待ち受け、待ち受けの住所を変える引数が無い。既定のまま使い、`01-listen.txt` に記録する。
- 起動すると、組 (pairing) の URL と、ブラウザ用の画面の URL が出る。どちらにも、この Orca を操作できる符号が入っている。報告書と証拠に書かない。どこに出たか (journal の行、`--json` の項目名) だけを書く。

## アカウント

- `orca account add` を使わない。Orca が自分の管理する別の home に認証を作るため、共通の指示 2.3 の「認証の複製を増やさない」に当たる。
- Claude Code と Codex は、Orca の "System default" のアカウント (環境変数の場所の認証) で動かす。それで動かなければ、Orca の出した文言を記録し、その試用を未実施とする。

## Claude の動かし方の決まり

- Claude は端末のタブ (Claude Code の実行ファイルをそのまま PTY で動かす経路) で動かす。
- 設定 `experimentalStructuredNativeChat` を入れない (既定は false)。入れると、Agent SDK を通して Claude を動かす経路になる。Chat UI (`experimentalNativeChat`) は PTY のまま動くので入れてよく、入れたら記録する。

## Orca が書き足す設定

- Orca は状態 (working、waiting、done) を表示するために、`~/.claude/settings.json` に hook と status line を、`~/.codex/hooks.json` と `~/.codex/config.toml` に hook と信頼の設定を書き足す。作業場所を Claude Code の信頼済みにする印を `CLAUDE_CONFIG_DIR` の `.claude.json` に書き足す。HOME の symlink を辿るので、どれも認証の複製のディレクトリに書かれる。これは製品が自分の仕組みで行う書き込みで、この走行では止めない。Codex 自身はこれらのファイルを読まず、変えない。
- 試用の初めと終わりに `orca-ide agent hooks status --json` の出力を取る。試用の終わりに `orca-ide agent hooks off --json` で Orca の hook を外し、もう一度 status を取る。証拠: `10-hooks.txt`。

## 操作

- この走行は、他の製品の走行と同時に動かさない。Orca は動いている間、上の設定を書き直し続けるので、同じ設定を使う他の製品の結果と混ざる。
- Orca は Claude を `--dangerously-skip-permissions`、Codex を `--dangerously-bypass-approvals-and-sandbox` 付きで起動する。初めて使うときに CLI がこの使い方への同意を求める画面を出したら、Orca の端末の中で同意し (CLI 自身が記録する。共通の指示 3 の 2 と同じ扱い)、出た画面の文言を報告書に書く。
- 試用の操作は、Orca の CLI (`~/v03/orca/squashfs-root/resources/bin/orca-ide`。使い方は `--help` と `orca-ide skills get orca-cli --full` で読む) か、`orca serve` が配るブラウザの画面 (Playwright) で行う。
- T3 と T5 の止め方は、端末への Esc か Ctrl-C (画面の操作か CLI の端末への送信) とする。
- T9 は Orca の orchestration で行う。Experimental の設定で有効にする必要がある。画面の無いマシンでは Settings の画面が無いので、CLI か Orca の設定ファイルで有効にする方法を探し、見つからなければそのことを書く。手順は `orca-ide skills get orchestration --full` で読む (`run-create`、`task-create`、`worker-start --agent claude` と `--agent codex`、`check --wait`、`worker-read`、`worker-stop`)。
- スマホへのプッシュ通知は、画面の無いサーバでは出ないと公式文書にあるので試さない。
