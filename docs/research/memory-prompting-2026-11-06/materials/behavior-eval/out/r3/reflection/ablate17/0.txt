メモリのファイルと索引の行を、次のとおり書きます。

メモリを書く前の書き出しは、次のとおりです。
- **働く場面**: 「〜が増えた・遅くなった原因を調べて」という調査依頼です。
- **メモリが無いときの挙動**: リリースや日時を原因として答えます。
- **働くべきでない隣の場面**: 「いつから増えたか教えて」という時点だけを尋ねる依頼です。

このセッションにはツールがないので、Sonnet での有り無しの比較試験はしていません。次に調査依頼が来たときに試験します。

**ファイル: `~/.claude/memory/feedback-cause-names-process.md`**

```markdown
---
name: feedback-cause-names-process
description: 性能劣化や障害の原因を答える文に、リリースや日時ではなく、どの処理が何をして起きたかを書く
metadata:
  node_type: memory
  type: feedback
---

- 原因を答える文に、どの処理が何をして遅く (または失敗) したかを書く
- リリース・バージョン・日時を、原因ではなく「発生時点」として別の文に書く
- 処理を特定できていない原因の欄に「未特定」と書き、特定できた事実と次に調べる箇所を並べる
```

**索引: `~/.claude/MEMORY.md` に追記する行**

```markdown
- [原因は処理で書く](memory/feedback-cause-names-process.md) — 性能劣化や障害の原因を答える文に、リリースや日時ではなく、どの処理が何をして起きたかを書く
```

決済 API のタイムアウトの原因は、まだ特定できていません。v2.3 のどの処理が何をして遅くなったのかは、コードと計測を見て調べる必要があります。調べるまでは、原因は「未特定」です。
