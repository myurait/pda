## ファイル 1: `~/.claude/memory/cause-names-process-not-release.md`

```markdown
---
name: cause-names-process-not-release
description: 障害や性能劣化の原因を答えるとき、リリースや日時ではなく、どの処理が何をしてそうなったかを書く
metadata:
  node_type: memory
  type: feedback
---

原因を答える文に、どの処理が何をして結果を起こしたかを書く。
リリースの版や日時を、原因ではなく発生時点として書く。
処理を特定できていない原因に「未特定」と書き、特定できている範囲と次に調べる対象を並べる。

**Why:** 決済 API のタイムアウト調査で「原因は v2.3 のリリース」と答えたところ、ユーザーから「リリースは時点であって原因じゃない」と指摘された。ユーザーが知りたいのは、どの処理が何をして遅くなったのかである。
**How to apply:** 障害、遅延、エラー増加の原因を聞かれたら、変更の差分やログから処理まで掘り下げてから答える。掘り下げられていなければ、「11/3 の v2.3 以降に増加。原因の処理は未特定」のように書く。
```
