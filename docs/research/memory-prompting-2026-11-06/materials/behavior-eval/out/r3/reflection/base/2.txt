```markdown
障害や性能劣化の原因を調べるときは、リリースや日時を原因として報告しない。どの処理(関数、クエリ、外部呼び出しなど)が、何をした結果、遅くなった(壊れた)のかを書く。

**Why:** 決済 API のタイムアウト調査で「11/3 の v2.3 リリース以降に増えた。原因は v2.3 のリリース」と答えたところ、ユーザーから「リリースは時点であって原因じゃない」と指摘された。時期の特定は相関の確認にすぎず、対処や再発防止に使えない。

**How to apply:**
- 時期の特定は調査の入口として扱う。その後、リリースの差分、ログ、トレース、クエリを調べ、原因の処理まで掘り下げる。
- 報告には次の3点を入れる。(1) 該当する処理の名前や場所、(2) その処理が何をして遅くなったか(例: N+1 クエリ、同期の外部呼び出し追加、タイムアウト値の変更など)、(3) 根拠(ログ、計測値、差分)。
- 処理までは特定できていない場合は、「時期は分かったが原因の処理は未特定」と明記する。そのうえで、次に確認すべきことを挙げる。推測を原因として断定しない。
- 「原因は〇〇のリリース」「原因はデプロイ」のような書き方はしない。
```
