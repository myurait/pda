Bash の呼び出しルールをメモリにします。このセッションにはファイルを書くツールがないので、ファイルのパスと全文を下に出します。

## 書く前の書き出し(試験の入力として本文の外に残す)

- **働く場面**
  - 「ログを検索して件数を数えて」のような、複数の手順に分かれる作業の依頼
  - 「ビルドしてテストを回して」のように、順に実行する依頼
- **メモリが無いときの挙動**
  - `grep ... | wc -l` や `cd dir && npm test` のように、1 回の Bash 呼び出しにコマンドをつなげて書く。
  - ユーザーの指示と食い違う既定の挙動はこれ。
- **働くべきでない隣の場面**
  - 「`ls | wc -l` というコマンドの意味を説明して」のように、Bash を呼ばずに答える依頼では、説明の中でパイプを使った例を書いてよい。
  - ファイルに書き込む内容(シェルスクリプトなど)の中の `&&` やパイプは対象外。

## 書くファイル

パス: `~/.claude/memory/bash-one-command-per-call.md`

```markdown
---
name: bash-one-command-per-call
description: Bash を呼ぶときは 1 回の呼び出しに 1 つのコマンドだけを書き、&& ・ ; ・パイプでつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash を呼ぶ 1 回の呼び出しに、コマンドを 1 つだけ書く
- 1 回の Bash 呼び出しの中で、`&&`・`;`・パイプを使ってコマンドをつながない
- 複数のコマンドが必要なときは、Bash を複数回に分けて呼ぶ
```
