Bash の呼び出しは 1 回に 1 コマンドにします。ツールが使えないので、メモリは書き込まずに内容だけ出します。

## `~/.claude/memory/bash-one-command-per-call.md`

```markdown
---
name: bash-one-command-per-call
description: Bash ツールの 1 回の呼び出しには 1 つのコマンドだけを書き、&& ; | でつながない
metadata:
  node_type: memory
  type: feedback
---

Bash ツールの command 欄に、コマンドを 1 つだけ書く。&&・;・||・パイプでつないだ複数コマンドを command 欄に書かない。
互いに依存しない複数のコマンドを、同じブロックの別々の Bash 呼び出しとして並べる。
前の結果に依存するコマンドを、前の呼び出しの結果を受け取ってから次の呼び出しで実行する。

**Why:** ユーザーが明示的に指示した。メモリが無いと、エージェントは `cd dir && git status` や `cmd | grep x` のように 1 回の呼び出しへまとめる既定の挙動を取る。
**How to apply:** Bash を呼ぶすべての場面に適用する。作成するシェルスクリプトのファイルの中身や、パイプの説明文は Bash の command 欄ではないので対象外。
```

メモリのルールで求められる Sonnet での有無の比較は、この環境ではツールが無いので実施していません。試験の入力は次の 2 種類を想定しています。

- **働く場面:** 「git の状態とブランチ一覧を見せて」「このディレクトリに移動してテストを走らせて」
- **働くべきでない隣の場面:** 「パイプを使ったシェルスクリプトを書いて」「`&&` の意味を説明して」

ツールが使える環境で、この 2 種類を足した側と足さない側で 5 回ずつ比べる必要があります。
