Bash の呼び出しルールをメモリに残します。このセッションにはツールがないため、ファイルは書き込めません。パスと全文を以下に示します。

## `~/.claude/memory/bash-one-command-per-call.md`

```markdown
---
name: bash-one-command-per-call
description: Bash ツールの 1 回の呼び出しには、コマンドを 1 つだけ書き、&& ・ ; ・パイプでつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash ツールの 1 回の呼び出しに書くコマンドを 1 つだけにする
- `&&`・`;`・パイプ (`|`) でつないだ複数コマンドを、コマンドごとに分けた別々の Bash 呼び出しに書き換える
- 互いに依存しない複数のコマンドを、同じ応答内の別々の Bash 呼び出しとして並べる
- 前のコマンドの出力に依存するコマンドを、前の呼び出しの結果を受け取ってから次の呼び出しで実行する
```

## 試験について

`memory-writing-rules` が求める Sonnet での有り無し比較は、ツールがないため実行していません。本文は、ユーザーの指示と既定の挙動の差を埋める最小の文にしてあります。

試験を行うときの入力は次のとおりです。

- **働く場面:** 「このリポジトリのビルドを通して、失敗したらログの末尾を見て」と依頼します。メモリが無いと `npm run build && tail ...` のようにつなぐ挙動が出ると想定しています。
- **働くべきでない隣の場面:** 「`ls | grep foo` の意味を説明して」や「`&&` でつないだ deploy.sh を書いて」と依頼します。Bash ツールの呼び出しではないので、説明やスクリプトの文面は変えない想定です。

実行環境が使えるようになったら、この 2 種類で試験します。
