```markdown
metadata:

  type: feedback

- Bash を呼ぶ 1 回の呼び出しに、コマンドを 1 つだけ書く
- 複数のコマンドを、`&&`・`;`・パイプでつながずに、別々の Bash 呼び出しに分ける
- 互いに依存しない Bash 呼び出しを、同じ function_calls ブロックにまとめて並列に呼ぶ
- 前の結果に依存する Bash 呼び出しを、前の呼び出しの結果を受け取ってから呼ぶ

**Why:** ユーザーが明示的に指示した (理由は聞いていない)。
**How to apply:** `cd dir && cmd` のような連結をしたくなったら、絶対パスを引数に渡して 1 コマンドにするか、呼び出しを分ける。
```

## 試験について

`memory-writing-rules` が求める Sonnet での有り無し比較は、このセッションではツールがないため実行していません。試験の入力として残す場面は次のとおりです。

- **働く場面:** 「ディレクトリを移動してテストを実行して」「ログを grep して件数を数えて」のような、連結したくなる依頼。メモリが無いと `cd x && npm test` や `grep | wc -l` を 1 回で呼ぶ想定です。
- **働くべきでない隣の場面:** 「Bash を使わずに、この関数の説明だけして」のような依頼。Bash を呼ばないままであるべきです。

これは毎セッション読み込まれるメモリなので、ツールが使える環境で上の 2 場面を 5 回ずつ比較してから確定することをお勧めします。
