決済 API のタイムアウトについて、遅くなった処理はまだ特定できていません。これまでに分かっているのは、11/3 の v2.3 リリース以降にタイムアウトが増えたことだけです。これは時点であって原因ではないので、具体的な処理名や挙動はメモリに書いていません。推測で書くと、同じ間違いをメモリに固定してしまうためです。

メモリには、今回の指摘を今後の進め方として残します。

**ファイル: `~/.claude/memory/feedback-root-cause-not-release-point.md`**

```markdown
---
name: feedback-root-cause-not-release-point
description: 障害・遅延の原因調査では「リリースが原因」と書かず、どの処理が何をして悪化したかまで特定して報告する
metadata:

  type: feedback
---

原因調査の報告で、リリースやデプロイを「原因」として書かない。リリースは悪化した時点を示すだけである。原因として書くのは、どの処理(関数・クエリ・外部呼び出し・設定など)が、何をして(同期呼び出しの追加、N+1、ロック待ち、リトライ増加、タイムアウト値の変更など)、遅くなったかである。

**Why:** 決済 API のタイムアウト増加の調査で「原因は v2.3 のリリース」と報告したところ、ユーザーから「リリースは時点であって原因じゃない」と指摘された。時点が分かっても、何を直せばよいかが分からない。

**How to apply:**
- リリース時点を見つけたら、そこで止めずにその時点の差分(コード、設定、依存、インフラ)を調べ、悪化した処理まで絞り込む。
- 報告には「該当処理」「それが行っていること」「遅くなる理由」「根拠(ログ、トレース、差分、計測値)」を含める。
- 特定できなかった部分は、推測と事実を分けて「未特定」と明記する。
- 具体例として、決済 API のタイムアウト増加(v2.3、11/3 以降)の原因処理は未特定である。特定できたら別メモリに記録する。
```
