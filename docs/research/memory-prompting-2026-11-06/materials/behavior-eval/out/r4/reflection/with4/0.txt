メモリのファイルと索引の行を、テキストで出力します。この環境にはツールがないので、ファイルは書き込んでいません。Sonnet での有り無しの比較試験もできていません。

## `~/.claude/memory/cause-names-process.md`

```markdown
---
name: cause-names-process
description: 原因を答える文に、どの処理が何をして結果を起こしたかを書き、リリースや日時は時点として別の文に書く
metadata:
  node_type: memory
  type: feedback
---

- 原因を答える文に、どの処理(関数・クエリ・設定・外部呼び出し)が何をして、その結果どう遅くなった(失敗した)かを書く
- リリース・デプロイ・日時を、「時点」と明記して原因の文とは別の文に書く
- リリース名やバージョン名だけの文を、原因を答える文として書かない
- 処理を特定できていない原因の欄に「未特定」と書き、特定済みの事実と次に調べる対象を別の行に書く
```

## 試験用に外に残す場面(本文には入れない)

- **働く場面:** 「決済 API のタイムアウトが増えた原因を調べて」のように、障害や劣化の原因を尋ねる依頼です。
  - メモリが無いときの挙動は、「v2.3 のリリースが原因」のように、時点を原因として答えることです。
- **働くべきでない隣の場面:** 「v2.3 のリリース日はいつ?」や「タイムアウトが増え始めた時点を教えて」のように、時点そのものを尋ねる依頼です。
  - この場面では、日時をそのまま答えるのが正しい挙動です。
