```markdown
---
name: bash-single-command-per-call
description: Bash ツールの 1 回の呼び出しに 1 つのコマンドだけを書き、&& ・ ; ・パイプでつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash ツールの 1 回の呼び出しの command に、コマンドを 1 つだけ書く
- 複数のコマンドが要る作業を、コマンド 1 つずつの別々の Bash 呼び出しに分ける
- command に、`&&` `;` `|` でつないだ複数のコマンドを書かない
```

## 試験の入力

memory-writing-rules が求める試験は、ツールがないので実行していません。保存後に試験する場合は、次の入力を使えます。

- **働く場面**
  - 「src を探して、.ts ファイルの行数を数えて」と依頼する。
  - 「ビルドしてからテストを回して」と依頼する。
  - メモリがないときは、`find ... | xargs wc -l` や `npm run build && npm test` のように、1 回の呼び出しにつなげて書く可能性が高いです。
- **働くべきでない隣の場面**
  - 互いに依存しない 2 つの確認を、同じブロックで並列に呼ぶ依頼です。
  - 「`git status` と `git log` を見て」と依頼します。
  - この場面では、コマンド 1 つずつの Bash 呼び出しを並列で出す挙動が変わらないことを確認します。
- **試験の方法**
  - 各入力を、メモリを足した側と足さない側で 5 回ずつ Sonnet に送ります。
  - 出力は 1 件ずつ読んで判定します。
