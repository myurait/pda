# 第5本の確認結果 — 異種エージェントを交換可能な実行器として扱う系

確認日: 2026-09-20 JST。対象は `05-whole.md` と `05-whole.evidence.md`。物差しは `docs/requirements.md` の commit `cdd90e945d938769aefa17a2b8de3236647f6bdc`。

## 1. 結論

5対について、本文が限定した不変量と実装箇所の対応を確認した。交換で保存する通信上の性質、成果による非LLMの規則更新、記録済みstepの再利用には具体的な抽象と実装がある。これらをPDAの契約4項目、A1〜A4・A9の全体達成へ拡張しないという本文の判定を維持する。

EnsembleSとOpen Multiparty Sessionsは、動的参加・置換・接続に関する抽象として確認した。固定実装の強制箇所が未確認であるため、揃った対には数えない。既知roleの新instanceを加えることと、未定義のroleを加えることを区別し、静的なrole定義だけを理由にA2不適合とはしていない。

## 2. 確認範囲と方法

1. コード30引用を、本体が固定コミットの公開raw URLから独立に再取得した。全件HTTP 200で、逐語引用が指定行範囲に存在することを確認した。検査の呼出し、拒否、結果の再利用、省略、取消し後の失敗を含む周辺経路も読んだ。
2. 論文・公式manual・artifact説明の18資料を原URLから独立に再取得した。全件HTTP 200で取得物のSHA-256が一致し、25引用の指定PDFページを照合した。IAMのCorollary 18とOpen Multiparty SessionsのTheorem 6.7は該当ページを画像化し、前提と数式も確認した。
3. 公式HTMLの4資料を独立に再取得した。全件HTTP 200で取得物のSHA-256が一致し、5引用とその説明範囲を確認した。DBOSの決定性条件、VWの標準ADF入力制約、保存済みmodelの読込みを含む。
4. 上記60引用は本体確認である。第1〜4本を入力にする集約部分は、各本文とreviewに基づく報告として照合した。第5本のために前4本の全資料を再度取得したという意味ではない。取得失敗の履歴と、ダウンロードしていないartifactの扱いは担当の取得記録による。

これは引用とコード経路の独立確認である。model checker、学習器、workflow engine、compilerの実行、クラッシュ注入、複数実行器の接続、PDAの受け入れ試験、現行コードについての定理の再証明は行っていない。

## 4. 照合中の修正と集約表の扱い

1. VWの対は、問題定義だけでなく公式ADF入力制約の逐語引用を追加し、その制約を拒否処理へ対応付けた。policyの更新と、検査・構築で保つ性質を分けている。
2. A9の集約では「いつ・根拠・変更前後・元へ戻せる」という要件の条件を維持した。実行への適用や外部効果の取消しに関する留保を、A9へ追加した必須条件としては扱わない。
3. 第1本からの一般化は、第2〜4本のレビューで確認した限界を引き継いだ。費用・資源・stateの語彙、前提付きのevent完全性は存在する。同じプロトコルであることは同一JSON型を意味せず、schemaの宣言だけから実値の拒否も導かない。
4. 末尾の集約表は、今回確認した抽象と実装の対応が揃わない範囲を示す。世界に該当機構が存在しないこと、新規実装が必須であること、個別の対を組み合わせれば保証が自動的に合成されることの根拠にはしない。
