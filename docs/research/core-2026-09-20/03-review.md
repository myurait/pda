# 第3本の確認結果 — ランタイムのラッパー

確認日: 2026-09-20 JST。対象は `03-runtime-wrapper.md` と `03-runtime-wrapper.evidence.md`。物差しは `docs/requirements.md` の commit `cdd90e945d938769aefa17a2b8de3236647f6bdc`。

## 1. 結論

6系譜について、本文が限定した不変量と実装箇所の対応を確認した。A1・A2・A5や契約4項目の全体を達成したとは認定しない、という本文の判定を維持する。受信した不正値の検査、正常な形を保った情報の脱落、そもそも生成されないeventの欠落を分けた説明は、確認したコードに整合する。

## 2. 確認範囲と方法

1. 根拠集の固定コミットを用い、コード・仕様56箇所を公開raw URLから本体が独立に再取得した。全件HTTP 200で、逐語引用が指定行範囲に存在した。引用の前後にある条件分岐・省略・失敗処理も読んだ。
2. POSIX.1-2024の3箇所を版固定URLから再取得し、HTMLの指定行、引用、取得物のSHA-256を照合した。
3. 論文3資料の4引用を独立に再取得した。同じSHA-256であること、取得版の指定ページに引用があることを確認した。Autili論文の改行で分割された単語は、PDFを画像化して確認した。
4. 上記63箇所は本体確認である。報告書担当の照合結果だけを再取得せずに引用確認済みとした箇所はない。取得失敗URLの応答履歴は担当の報告によるもので、本体は再試行していない。

これはコード読解と引用照合であり、各ランタイムの起動、異なるadapter同士の相互運用、故障注入、PDAの受け入れ試験を実施した意味ではない。実行時のスキーマ検査に関する記述も、実装経路の確認に基づく。

## 4. 照合中の修正と第1本からの留保

1. Autili論文の引用台帳にあった総ページ数9を、取得PDFの8ページへ修正した。本文と根拠集には修正済み。引用位置はPDF物理1ページ、冊子79ページで変わらず、結論への影響はない。
2. SDKにスキーマ検査があることを、任意フィールドの不正も全て拒否する保証へ拡張していない。`vecSkipError`と`defaultOnError`の例外を本文と根拠集の両方に記載済みである。
3. 第1本の「仕事と成果が別の型であることから同じプロトコルではないと判定する」推論は継承していない。要件が要求するのは同じプロトコルに基づくメッセージであり、同一のJSON型ではない。
4. 最小契約の外に置かれた範囲は確認できるが、それが成功を生んだという因果的主張は未検証として残した。普及や成功の理由まで実装箇所から導いていない。

## 5. 第5本への扱い

第5本では、部分的な接続・型・状態遷移の保証として利用できる。A1の記憶・可視化・監査まで含む交換可能性や、event streamの欠落検知が完成していることの根拠にはしない。詳細なURL、固定SHA、逐語引用、ページ位置は [根拠集](03-runtime-wrapper.evidence.md) を参照する。
