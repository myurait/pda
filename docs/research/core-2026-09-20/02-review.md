# 第2本の確認結果 — MCP 的な自己宣言

確認日: 2026-09-20 JST。対象は `02-self-declaration.md` と `02-self-declaration.evidence.md`。物差しは `docs/requirements.md` の commit `cdd90e945d938769aefa17a2b8de3236647f6bdc`。

## 1. 結論

10対について、宣言と登録情報の照合、宣言と入出力値の適合検査、権限に応じた操作の拒否を、それぞれ本文が限定した範囲で確認した。これらは同じ種類の保証ではなく、宣言が検査を通ったことだけで外部実行器の能力・費用・権限・再開可能性の真実性を保証しない、という結論を維持する。

費用・到達資源・stateには個別の既存語彙と実装がある。第1本の広い未発見の記述を、語彙そのものの不在として継承してはならない。本調査で未発見なのは、要件が定義する実行器の単位に結び付き、必要な宣言と実態の検査が一つの契約として揃う対である。

## 2. 確認範囲と方法

1. 根拠集の固定コミットにあるコード・仕様65箇所を、本体が公開raw URLから独立に再取得した。全件HTTP 200で、逐語引用が指定行に存在することと、検査・例外・省略の経路を確認した。
2. FIPAの保存時刻付きアーカイブとWSDLの版固定URLから、HTMLの3引用を独立に再取得した。全件HTTP 200で、指定行の引用を確認した。
3. 論文・歴史的コード5資料の8引用を原URLから独立に再取得した。全件HTTP 200、取得物のSHA-256が一致し、指定PDFページの引用を確認した。1978年CNETコードの物理7・44・52ページは画像化し、条件照合、task announcementのゲート、task process pointerへの継続操作を目視した。
4. 上記76引用は本体確認である。icontractの3ケースの実行結果は担当の報告として採用し、本体による再実行結果とはしていない。コード上の前条件・後条件・無効化経路は本体で再取得して確認した。取得失敗URLの履歴も担当の報告である。

このレビューは引用とコード経路の確認であり、各サーバーの起動や相互運用、クラスタでの配置、OSのアクセス拒否、compilerやemulatorの実行、実請求、クラッシュ後再開を試験したものではない。

## 4. 全体評価に引き継ぐ留保

1. 初稿はA4を解析・検査・配置等が特定LLMなしに動く範囲で「満たす」としていた。条件全文は判定用実行器を差し替えてもコアが動くことも含むため、部分機構の確認に対応する「一部」へ修正した。第3・4本と同じ基準で、条件全体と部分的な保証を区別する。
2. 要求と応答が別の型であること、clientからserverへtoolを呼ぶ方向であることだけでは、要件の仕事・成果の共通プロトコルに反すると判断しない。対象の境界と、そこに実際にある検査を評価する。
3. 既存APIへの登録追加、同じ役割の追加、別アカウント・別環境・別エージェントを一単位として扱う追加は区別する。A2の部分適合をそのまま全体達成とはしない。
4. MCPの再試行、Tasksの照会再開、Kubernetesの再起動、CNETの継続はいずれも実在するが、同じ復旧能力ではない。stateの語彙の存在と、中断後の内部状態復元能力の検査を分ける。

詳細なURL、固定SHA、逐語引用、取得版のページ位置は [根拠集](02-self-declaration.evidence.md) を参照する。
