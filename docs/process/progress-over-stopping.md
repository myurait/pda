# 開発の考え方: 進める機能と止めるための機能

- 更新: 2026-10-11 JST
- 種別: 開発の考え方の取り決め。PDA の開発で、機能を設計・実装するとき、試用や部品を作るときに使う。

## 取り決め

1. ユーザーが求めているのは常に進める機能、自走する機能である。
2. 止めるための機能は本当に必要で強いリスクがあるときに、ユーザーに提案して承認を得てから作成しなければならない。
3. AI は権限境界から、常に止めるための機能を作ることを作業コストやリスクが低いと見積もって作業を開始する傾向がある。これは逆行であるため、止めるための機能を作成するときにはこのバイアスを自覚し常に強い疑いを持たなければならない。

## 止めるための機能に当たるもの

- 依頼、道具の呼び出し、仕事の受け渡しを止める、または断る機能 (hook、権限の設定、検査、歯止め)。
- 承認や確認を求めて、作業を待たせる機能。
- ユーザーの指示より、別の判断 (判定モデル、規則、検査の結果) を優先させる機能。

## 作る前に行うこと

- 止めるための機能を設計や指示に書こうとしたら、それが無いと何が起きるか (リスク) と、その強さを書く。
- それをユーザーに提案し、承認を得てから作る。承認の無いまま、試用の一部や部品の一部として作らない。
- 同じ目的を、進める機能 (自走を助ける、判断の材料を足す、結果を知らせる) で果たせないかを先に考え、その案も提案に並べる。
