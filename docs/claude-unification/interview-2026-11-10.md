## 候補の元になった体験

使いづらさの感想は、PDA として整備する前に、ミニ PC のクロードコードのリモートセッションを個人契約のアカウントで試した体験から出ている。OpenClaw 上で整備した PDA は、開発 PC とのコネクタの確認と通知の確認で少し使ったが、感触が良くなくすぐにやめ、ナレッジも整備できていないので、何も動かしていない。

## OpenClaw の音声入力の経緯

11-10 の「音声入力とかの品質はいい」は、Claude の音声入力を指す。OpenClaw をやめた理由として音声入力を挙げた発言は、2026-10-01 以降のセッションの記録には無い。OpenClaw の音声入力については、次の発言がある (セッションの記録からの抜粋。音声入力の表記のまま)。

- 2026-10-17 (OpenClaw の音声入力を試して): 「トークを試してみたが、うんちょっと、かなり使いづらいというか、気持ち悪いので、使いたくない感じだったよ。えー、で、音声入力をちょっと試してみたが、音声入力をしてから、停止ボタンを押してテキストが出てくるまでに結構な時間があり、かつ、えー、その間何もインタラクションがないので、かなり厳しかった。」
- 2026-10-17 (Claude Code デスクトップアプリの音声入力について): 「入力したそばからテキストがどんどん記入されていって、おそらくこれは音声入力の入力したその生の データを直で変換して、リアルタイムに出力していっている感じなんだよね。で、それが最終的に、えー、マイクオフにして確定するとえー、さらに一回何かしらのフィルターが入って、最終的な文章に成形されるという挙動をしていそう。」同じ挙動が OpenClaw でできるかを調べさせた。
- 2026-10-18 (OS の音声入力を探させて): 「OpenClose 上の機能定義で渡っている音声入力に固執する必要はないのかもしれないね。」「今のところMacのOSの音声入力はちょっとしょぼいというか聞き漏らしが多くてですね。フィラーが入らないから悪くはないんだけど、漏らしがひどい。」
- 2026-11-05: 「Mac のネイティブの音声入力とは明らかに性質が違う。ことがわかる。フィラーの除去や句読点の入力など、の挙動が明らかに Mac デフォルトの音声入力の挙動ではないね。これはPDA の実装中にいくつか音声入力モデルを試したが、明らかにこれはクロードコード上の何らかの、ネイティブの音声入力とは違う中継が入っている。できればこれを生かす形にしたいんだが、ブラウザ版でもこれは同じ挙動なんだろうか。」

この間、OpenClaw の画面にはマイクのボタンを一度押すだけで音声入力を始めるプラグイン (plugins/openclaw/tap-to-dictate、2026-10-31) を足した。

## 要求の候補

### 目標と、PDA と開発 PC の分担

#### K1. すべての開発物の進行とナレッジを PDA 上に集約する

- オーナーの語: 「最終的に PDA 上にすべての開発物の進行とナレッジを集約したい」「それ以外の私の開発の主体は PDA 上に移すことが最終的な目標」「PDA 上に全てを集約して全ての作業を答え。」
- 根拠: 個人で受けている案件を開発 PC から PDA へ持っていこうとした理由として述べた。ナレッジの使い道は、PDA 上で全ての作業を行うこと (音声入力の「全ての作業を答え」を「全ての作業を行う」と読んだ)。
- 種別: 機能要件 (最終的な目標)

#### K2. 開発 PC は、会社のコネクタと、会社契約のアカウントで作るアーティファクトのために使う

- オーナーの語: 「開発 PC は、コネクタ、だったり、開発会社契約のアカウントで、作成しなければいけないアーティファクトだったりのために使う。前提で」
- 根拠: 同上。
- 種別: オーナーの条件 (3.1-6「会社のコネクタは開発 PC の Claude だけが使う」を、会社契約のアーティファクトの作成まで広げるもの)

#### K3. 途中まで進めた作業を、開発 PC から PDA へ持っていって続けられる

- オーナーの語: 「会社契約の PC の、クロード、コード上で途中まで作業していた内容を、PDA 上に持っていこうとした」
- 根拠: 個人で受けている案件 (会社契約のアカウントとは紐づいていない) を、開発 PC で途中まで進めていた。持っていく理由は K1。
- 種別: 機能要件

### 話しかけ方

#### K15. 音声で話した内容が、AI が受け取る指示として正しく取り込まれる。使い心地は Claude の音声入力に近い

- オーナーの語: 「それを AI が受け取る指示にすることが重要」「あんまり精度よく入力できてない内容を、うまく AI がこうだったのかなって、取り込んでくれるような仕組み」「再現はしないまでも、なんだか別の機構で、これに近い使い心地にしたい」
- 根拠: 前節の経緯。Claude の音声入力は、話したそばから文字が出て、確定するとフィラーが除かれ句読点の入った文章に整う。OpenClaw では停止を押すまで文字が出ず、OS の音声入力は聞き漏らしが多かった。
- 重み: 「あると嬉しい程度」。Claude の音声入力は「ズバ抜けていい」が、OSS も進化しているので「そこまでクロードに固執しなくていいのかもしれない」。入口を Claude にする理由としては重くない。
- 種別: 機能要件 (あると嬉しいもの)
- オーナーの実現の案 (設計で扱う): 2 つの音声入力エンジンと、それを統合する解釈用のモデルを 1 つのプロバイダーにまとめる。指示・言語・語彙・フィラーなどのノイズを除く仕組み。

### 入口とセッションの立ち上げ

#### K17. いつもの新規セッションを開く操作で始めても、文脈を継承できる

- オーナーの語: 「一本の長いセッションじゃなくて、いつもの新規セッションを開く操作で始めても、文脈を継承できるっていうことの重要さはある」
- 根拠: 「入口が 1 つ」を、1 本の長いセッションに話しかけ続けることではなく、どの新規セッションも同じ PDA に届くこと、と読んだ問いへの答え。
- 種別: 機能要件 (3.1-2「入口は、ミニ PC 上で動き続ける 1 つのセッション」を読み直す材料)

#### K18. スマホで、PDA 上の新しいセッションを、一段深掘る操作なしに立ち上げられる

- オーナーの語: 「PDA 上の別のセッションを新規で立ち上げようとしたときに、リモートデバイスの選択からそこで新規セッションをしないといけないっていう一段深掘る動きが必要になる」「マス層のユーザーは、ただ、クロードコードも使わず、クロードの通常の新規セッションをポチって押すだけだから、そもそも動きとして、一番上に来るように設定されてない」
- 根拠: スマホで PDA 上のセッションを管理しようとした。入口のセッションを立ち上げるにはよいが、PDA 上の別のセッションを新しく立てるには、リモートデバイスを選んでから新規セッションを開く必要がある。「リモートセッションを入り口にしないといけないところが使いづらい」(11-10) の本当の意図は、この画面上の話。
- 種別: 機能要件

### 画面

#### K16. 入口の画面は、細かいところの使いやすさに配慮が行き届いている

- オーナーの語: 「本当に細かいところの使いやすさなんだよな」「細かく配慮が行き届いてる感じというか、使い勝手悪いねっていう声のあるところをちゃんと潰してってる感じがあっていい」
- 根拠: Claude Code Desktop の良さとして挙げた例。hook が何のプロンプトを挿入しているのかの見やすさ、アーティファクト、インラインの Bash のターミナルの使い勝手、チャットの一覧のサブメニューが程よいこと、マーケットプレイスのコネクタを画面から選んで簡単に入れられること、MCP を入れるのが楽なこと。用件ごとのセッションやチャットの一覧は「他のチャットを使う系の OSS と UI でも、どこでもできている」ので良さに入らない。
- 困りごと: Desktop の細かい使いやすさを受けられるのは、会社契約でログインした開発 PC の Desktop だけで、PDA の作業には届かない (「おおむねそれで合ってる」)。「アーティファクトとかは、権限の都合で明確に使い勝手が悪くなってる」。オーナーはこの使いやすさを「言語化が難しい快適さ」と呼んでいる。
- 種別: オーナーの条件 (画面を選ぶ物差し。「画面を決め直す」(11-10) の材料)

### 規約

#### K4. PDA でも、普段の作業と同じフック・コミュニケーション規則・メモリが効いている

- オーナーの語: 「開発 PC 上にあるフックやコミュニケーション規則を遵守されない状態から仕事をするっていうのがきつかった」「コミュニケーション規則とか、アーティファクトで判断を、要求するようなルールみたいなところが、入ってなくて、普段の作業と違って使いづらかった」
- 根拠: 今の仕事は開発 PC 上のクロードコードで行っており、チャット・リポジトリ・「多少なりカスタムしたフックや、説明させるためのメモリの仕組み」がそろっている。個人で受けている案件を PDA 上に持っていくと、それらが入っておらず使いづらかった。
- 種別: 機能要件

### 応答の終端

#### K12. 応答の終端で、複数のゲートを通す。作業が終わったと言って終わっていなければ突き返し、ユーザーへのコミュニケーション規則に外れていれば差し戻す

- オーナーの語: 「複数の、応答集端ゲートを通らせたいのよ」「そもそも作業が終わったって言って、作業が終わってなかったりしたら突き返したい」「ユーザーに対してのコミュニケーション規則を遵守してもらうっていうフックで差し戻し」
- 根拠: 同上。
- 種別: 機能要件 (3.2-2 の規約の点検に、作業の完了の点検を加えるもの)

#### K13. 差し戻しを何度繰り返しても、チャットに出てヒストリーに残るのは最後の一通だけ

- オーナーの語: 「そもそも応答を出さないようにしたい。今は何かの応答が出てしまうんだよね」「差し戻し差し戻し差し戻しで繰り返し何度も差し戻しが入った後の最後の一通だけ ヒストリーに残っててほしい。し、最後の一通以外、チャットに出力してほしくない」

- オーナーの語: 「要は頭の中でやってることと、頭の中でやるべきことと、口に出して言うことの区別をつけるために、最終的な、出力が何になるかっていうのをある程度絞らないといけない」
- 根拠: K11〜K13 の理由として述べた。
- 種別: 機能要件 (K11〜K13 をまとめる目的)

### 会社のアカウントとアーティファクト

#### K5. 会社のアカウントで作ったアーティファクトを、PC でもスマホでも見られる

- オーナーの語: 「会社のアカウントでアーティファクトを作るっていう操作を結構やるのよ。会社の他のメンバーに共有しないといけないからね」「会社契約の作ったアーティファクトをそのままスマホで見れないんだよね」

- 種別: 機能要件

#### K6. 会社のアーティファクトは、組織に属するアカウントでしか見られない

- オーナーの語: 「リンクを知っている全員に共有は会社の方針的に使えないので、組織に属している必要がある」
- 根拠: 同上。
- 種別: オーナーの条件 (会社の方針)

#### K7. 他の人が作った会社のアーティファクトも確かめるので、ブラウザは会社契約でログインしておく

- オーナーの語: 「他の人が吐き出したアーティファクトを確認しないといけない場面もあるので、ブラウザで、持ってる、アンスロピックのログイン自体は会社契約のものにしておかないといけないよね」
- 根拠: 会社の案件でアーティファクトを出させるとき、ブラウザだけ会社契約にした。
- 種別: オーナーの条件

#### K8. PC で、会社のアカウントでログイン済みの開発 PC のクロードコードと並べて、PDA に話しかけられる

- オーナーの語: 「クロードコードデスクトップを2つ立ち上げる必要が出てしまって、でもそんなことできないから、つなげられずに、ブラウザでやろうとしたんだけど、まあなんかあんまりブラウザでやっても使い勝手良くなかった」「PDA のアカウントで表示している画面が少なくなってちょっと使いづらい」
- 根拠: 開発 PC のデスクトップアプリは会社契約でログイン済みで、隣でフックとメモリを調整済みのクロードコードが動いている。PDA のリモートセッションにつなぐにはデスクトップアプリがもう 1 つ要るが立ち上げられず、ブラウザは使い勝手がよくなかった。

## 入口の形ごとの良さと困りごと

3.1-1 (入口の画面) と 3.1-2 (入口は動き続ける 1 つのセッション) を書き直すための材料。オーナーが挙げた良さと困りごとを、オーナーの語で並べる。重みはまだ伺っていない。11-10 の「入口は 1 つのままがいい…claude リモートセッションでも問題ない」は、「こういうケースの時これでもいいなと思っている」という一次回答で、決定ではない。

Claude Desktop・Claude アプリのリモートのセッションを入口にする形

- 良さ: 「音声入力とかの品質はいい」(11-10)。Claude の音声入力を指す (K15)。重みは「あると嬉しい程度」
- 良さ: 「使い勝手としても Cloud Code Desktop の方がいい」(11-03。OpenClaw と比べて)。中身は細かいところの使いやすさ (K16)
- 良さ: 入口が 1 つになる。「スマホから届く入り口を一つにする」(11-03)、「入口は 1 つのままがいい」(11-10、一次回答)。良さの中身は、どの端末から話しかけても同じ相手に届き、頼んだ作業とオーナーの判断待ちがその相手のところに集まること (読みを「合ってる」と確かめた)
- 困りごと: 「PC、スマホ両方において、メインの新規セッションじゃなくて、リモートセッションを入り口にしないといけないところがそもそも使いづらい」(11-10)。本当の意図は、PDA 上の新しいセッションを立てるのに、アプリの主要な操作ではない一段深い操作が要ること (K18)
- 困りごと: 会社契約でログインした Desktop と並べられず、ブラウザは使い勝手がよくない (K8)。Desktop の細かい使いやすさが PDA の作業に届かない (K16)
- 困りごと: スマホのアプリを個人契約でログインすると、会社のアーティファクトを見られない (K5)
- 困りごと: 踏み台を経て、どのセッションに今いるのか混乱する (K9)
- 困りごと: 応答の終端の細かい使い方ができず、差し戻し前の応答もチャットとヒストリーに出て、通知も絞れない (K11〜K13)

OpenClaw を入口にする形 (v0.3)

- 困りごと: 「あんまり感触が良くなくてすぐに使うのをやめてしまった」(11-10)、Dreaming が使われていない (11-03)
- 困りごと: 音声入力は停止を押すまで文字が出ず、その間に何も反応が無い (10-17)
