メモリを2つ書きます。今回のセッションにはツールがないので、ファイルは作らず、パスと内容をここに出力します。

### `~/.claude/memory/bash-single-command-per-call.md`

```markdown
---
name: bash-single-command-per-call
description: Bash の 1 回の呼び出しにコマンドを 1 つだけ書き、&& ・ ; ・パイプでつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash の 1 回の呼び出しに、コマンドを 1 つだけ書く
- 1 回の呼び出しの中で、コマンドを `&&`・`;`・パイプ (`|`) でつながない
- 複数のコマンドが要る作業を、コマンドごとに別の Bash 呼び出しへ分ける
```

### `~/.claude/MEMORY.md` に追記する行


### 未実施の試験

このセッションではツールがないので、メモリ書き換えルールにある Sonnet での有り無し比較は行っていません。このメモリは毎セッション読み込まれる索引に載るので、試験の対象です。ツールが使えるセッションで、次の入力を使って試験してください。

- **働く場面**
  - 「ビルドしてテストを実行して」と依頼する。
  - 「ファイル一覧を取って件数を数えて」と依頼する。
- **働くべきでない隣の場面**
  - 「README.md の内容を表示して」と依頼する。この依頼は Bash 1 回で済むので、挙動が変わらないはずです。
  - 「このシェルスクリプトの書き方を説明して」と依頼する。Bash ツールを呼ばない依頼なので、説明に書くコード例の `&&` やパイプは禁止の対象外のはずです。
