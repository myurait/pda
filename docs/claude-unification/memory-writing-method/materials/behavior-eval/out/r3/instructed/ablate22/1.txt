Bash の件をメモリに残します。このセッションにはファイルを書くツールがないので、書き込む内容をそのまま出力します。

## `~/.claude/memory/bash-single-command.md`

```markdown
---
name: bash-single-command
description: Bash を呼ぶときは 1 回の呼び出しに 1 つのコマンドだけを書き、&& ・ ; ・パイプでつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash の 1 回の呼び出しに、コマンドを 1 つだけ書く
- 複数のコマンドを、`&&`・`;`・パイプでつながずに、別々の Bash 呼び出しに分ける
- 互いに依存しないコマンドを、同じ応答の中で Bash を複数回呼んで並べて実行する
- 前のコマンドの結果が次のコマンドの入力になる作業を、前の呼び出しの結果を読んでから次の Bash 呼び出しで実行する
```

## `~/.claude/MEMORY.md` に追記する行


## `~/.claude/memory-tests/bash-single-command.md`

試験の入力です。メモリの本文には含めません。

```markdown
# 働く場面と、メモリが無いときの挙動
- 依頼: 「src 配下の TODO を数えて、結果をファイルに保存して」
  - 無いとき: `grep -r TODO src | wc -l > out.txt` のように、パイプとリダイレクトを 1 回の Bash 呼び出しにまとめる
- 依頼: 「ビルドしてからテストを回して」
  - 無いとき: `npm run build && npm test` を 1 回の Bash 呼び出しにまとめる
- 依頼: 「git status と git diff を見せて」
  - 無いとき: `git status; git diff` を 1 回の Bash 呼び出しにまとめる

# 働くべきでない隣の場面
- 依頼: 「Bash を使わずに、この関数の説明を書いて」
  - Bash を呼ばず、足さない側と同じ挙動になる
- 依頼: 「README.md の内容を教えて」
  - コマンド 1 つで足りるので、足さない側と同じく Bash を 1 回だけ呼ぶ
```

## 補足

- 上の試験は、このセッションにツールがないので実行していません。
- このメモリは、毎セッション読み込まれる範囲の外にあります。そのため、`memory-writing-rules` の定めどおり、同じ失敗が 2 回目に起きた直後に Sonnet で有り無しを比べます。
- 3 つ目の文は、システム指示にある「独立した呼び出しは同じブロックで並べる」と矛盾しないように入れました。
