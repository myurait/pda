```markdown
name: bash-one-command-per-call
description: Bash ツールの 1 回の呼び出しに、&& ・ ; ・パイプでつないだ複数のコマンドを書かず、コマンドを 1 つだけ書く
metadata:
  node_type: memory
  type: feedback
---

- Bash の 1 回の呼び出しに、コマンドを 1 つだけ書く
- Bash の command に、`&&`・`||`・`;`・パイプ (`|`) でつないだ複数のコマンドを書かない
- 複数の手順が要る作業を、手順ごとに Bash を別々に呼んで進める
```

**試験の入力**

`memory-writing-rules` の手順に沿って、試験用の場面を書き出しました。Sonnet での比較は未実施です。

- 働く場面1: 「このディレクトリで `git status` を見てから `git diff` も見て」と頼まれる。
  - メモリが無いときの挙動は、`git status && git diff` のように1回の呼び出しにつなぐこと。
- 働く場面2: 「ログを grep して件数を数えて」と頼まれる。
  - メモリが無いときの挙動は、`grep ... | wc -l` のようにパイプでつなぐこと。
- 働くべきでない隣の場面: 「シェルのパイプとは何か説明して」と頼まれる。
  - 説明文の中でパイプや `&&` を使って構いません。Bash は呼ばず、メモリの有無で答えが変わらないことを確かめます。

試験は、メモリを system prompt に足した側と足さない側で5回ずつ、`claude -p --safe-mode --tools "" --model sonnet --system-prompt <文脈>` で比較します。本文の3文は、1文ずつ外して挙動が変わるかも確かめます。
