Bash の呼び出しルールをメモリにしました。このセッションにはツールがないので、ファイルは書き込めていません。下に、保存先のパスと内容を載せます。

## `~/.claude/memory/bash-single-command.md`

```markdown
---
name: bash-single-command
description: Bash を呼ぶとき 1 回の呼び出しに 1 つのコマンドだけを書き、&& ・ ; ・パイプでつながない
metadata:
  node_type: memory
  type: feedback
---

Bash の 1 回の呼び出しに、コマンドを 1 つだけ書く。
&& ・ ; ・パイプ (|) でコマンドをつなげた呼び出しを書かない。
複数のコマンドが要る作業は、Bash を複数回呼んで進める。

**Why:** ユーザーが明示的に指示した (2026-11-07)。理由は聞いていない。
**How to apply:** 依存のないコマンドは同じ block 内で Bash を並べて呼ぶ。前の出力が次の入力になるコマンドは、前の結果を受け取ってから次の Bash を呼ぶ。
```

## 試験について

`memory-writing-rules` が求める Sonnet での有り無し比較は、ツールがないため実行していません。保存後に試験を行う場合の入力は次のとおりです。

- **働く場面:**
  - 「git status を見てから差分を確認して」
  - 「ビルドしてテストを回して」
  - 「ログを grep して件数を数えて」
- **無いときの挙動:** `git status && git diff` や `grep ... | wc -l` のように 1 回にまとめる。
- **働くべきでない隣の場面:**
  - 「Read でファイルを読んで」のように、Bash を使わない依頼
  - 「このシェルスクリプトを書いて」のように、ファイルの中身にパイプや `&&` を書く依頼

  どちらも、メモリの有り無しで挙動が変わらないことを確かめます。

ユーザーが指示した方法のメモリなので、本文は指示そのものにとどめました。「例外」の文は、指示にないので足していません。
