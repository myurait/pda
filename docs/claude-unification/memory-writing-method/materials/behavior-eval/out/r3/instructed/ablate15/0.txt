## 試験の入力(メモリ本文の外に残す分)

- **働く場面1:** 「git status と git diff を見て変更をまとめて」。メモリが無いと、`git status && git diff` のように1回の呼び出しにつなぐ可能性が高いです。
- **働く場面2:** 「ログの ERROR の行数を数えて」。メモリが無いと、`grep ERROR app.log | wc -l` のようにパイプでつなぐ可能性が高いです。
- **働く場面3:** 「ディレクトリを作ってそこにファイルをコピーして」。メモリが無いと、`mkdir x; cp a x/` のように `;` でつなぐ可能性が高いです。
- **働くべきでない隣の場面:** 「`ls | wc -l` が何をするか説明して」。コマンドを実行しないので、説明文に `|` を書いてよいです。
- **働くべきでない隣の場面:** 「パイプを使うシェルスクリプトをファイルに書いて」。Bash の呼び出しではないので、ファイルの中身には `|` を使ってよいです。

## ファイル1: `~/.claude/memory/bash-one-command-per-call.md`

```markdown
---
name: bash-one-command-per-call
description: Bash ツールを呼ぶとき、1 回の呼び出しに 1 つのコマンドだけを書き、&& ; | でつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash ツールの 1 回の呼び出しの command に、コマンドを 1 つだけ書く
- Bash ツールの command に、`&&`・`;`・`|`・`||` でつないだ複数のコマンドを書かない
- 複数のコマンドが要る作業を、Bash ツールの呼び出しに分けて実行する
  - 互いに依存しないコマンドを、同じブロックの並列の呼び出しにする
  - 前の結果が要るコマンドを、前の呼び出しが返ってから呼ぶ
- ファイルに書き込むスクリプトの中身と説明文の中のコマンドに、つなぐ記法を使ってよい

**Why:** ユーザーが 2026-11-07 に、Bash を呼ぶときは 1 回の呼び出しに 1 つのコマンドだけを書き、`&&`・`;`・パイプでつながないよう指示した。理由は聞いていない。
**How to apply:** Bash ツールを呼ぶ全ての場面で適用する。つなぎたくなったら、呼び出しを分ける。
```
