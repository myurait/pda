Bash の呼び出しルールをメモリにしました。このセッションにはツールがないので、ファイルは書き込めていません。以下の内容を手動で配置するか、ツールのあるセッションで書き込んでください。

## `~/.claude/memory/bash-one-command-per-call.md`

```markdown
---
name: bash-one-command-per-call
description: Bash を呼ぶときは 1 回の呼び出しにコマンドを 1 つだけ書き、&& ・ ; ・パイプでつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash の 1 回の呼び出しの command に、コマンドを 1 つだけ書く
- Bash の command に、`&&`・`;`・`|` でコマンドをつなぐ記述を書かない
- 複数のコマンドが要る作業を、コマンドごとの Bash 呼び出しに分ける
- 前のコマンドの結果が要る呼び出しを、前の呼び出しの結果を受け取ってから行う
```

## `~/.claude/MEMORY.md` に追記する行

```markdown
- [Bash は 1 呼び出し 1 コマンド](memory/bash-one-command-per-call.md) — Bash を呼ぶときは 1 回の呼び出しにコマンドを 1 つだけ書き、&& ・ ; ・パイプでつながない
```

## 試験の入力

メモリ規約にある試験は未実施です。ツールがないので、Sonnet でメモリの有無を比べられていません。試験用の場面は次のとおりです。

- **働く場面**
  - 「依存パッケージを入れてテストを走らせて」
  - 「`git status` と `git diff` を見て」
  - 「ログから ERROR 行だけ数えて」
- **無いときの挙動**
  - `npm install && npm test` のように 1 回にまとめる。
  - `grep ERROR log | wc -l` のようにパイプでつなぐ。
- **働くべきでない隣の場面**
  - 「デプロイ用のシェルスクリプトを Write で作って」。ファイルの中身の `&&` は対象外です。
  - 「`&&` とパイプの違いを説明して」

最後の 4 つ目の文は、「前の結果が要るなら待つ」という既存の動作を明示したものです。試験で外しても挙動が変わらなければ削除してください。
