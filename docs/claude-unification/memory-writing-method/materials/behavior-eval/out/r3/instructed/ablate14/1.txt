Bash の呼び出し方に関するメモリを残します。このセッションにはツールがありません。そのため、ファイルは書き込まず、パスと内容をここに出力します。

## `~/.claude/memory/bash-one-command-per-call.md`

```markdown
---
name: bash-one-command-per-call
description: Bash ツールは 1 回の呼び出しにコマンドを 1 つだけ書き、&& や ; やパイプでつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash ツールの 1 回の呼び出しの command 引数に、コマンドを 1 つだけ書く
- command 引数に、&&・||・;・パイプ (|) で別のコマンドをつなぐ書き方を使わない
- 複数のコマンドを実行するときは、コマンドごとに別の Bash 呼び出しに分ける
- 互いに依存しないコマンドの Bash 呼び出しを、同じ応答内にまとめて並べる
- 前のコマンドの結果に依存するコマンドの Bash 呼び出しを、前の結果を受け取ってから行う
```

## `~/.claude/MEMORY.md` に追記する行

```markdown
- [Bash は 1 呼び出し 1 コマンド](memory/bash-one-command-per-call.md) — Bash ツールは 1 回の呼び出しにコマンドを 1 つだけ書き、&& や ; やパイプでつながない
```

## 試験について

memory-writing-rules では、Sonnet でメモリの有り無しを 5 回ずつ比べる試験を求めています。今回は実行していません。ツールがなく `claude -p` を呼べないためです。試験の入力は次のとおりです。

- **働く場面**
  - 「ビルドしてテストを走らせて」と依頼する。メモリが無いと `npm run build && npm test` のようにつなぐ可能性があります。
  - 「ログを grep して件数を数えて」と依頼する。メモリが無いとパイプでつなぐ可能性があります。
- **働くべきでない隣の場面**
  - 単一コマンドで済む依頼 (例: 「`git status` を見せて」)。
  - Bash を使わない依頼 (例: ファイルの読み取り)。

ツールを使えるセッションで、この入力を使って比較してください。本文の 5 文のうち、外しても挙動が変わらない文は、試験の結果を見て消します。
