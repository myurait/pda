Bash の呼び出し方についてのメモリを作りました。この環境にはツールがないので、ファイルは書き込めていません。下に内容を出すので、保存はあなたにお願いします。メモリの書き方ルールにある Sonnet での有り無し比較も、同じ理由で実施していません。

## `~/.claude/memory/bash-single-command-per-call.md`

```markdown
---
name: bash-single-command-per-call
description: Bash ツールの 1 回の呼び出しには、&& ・ ; ・パイプでつながない単一のコマンドだけを書く
metadata:
  node_type: memory
  type: feedback
---

- Bash の 1 回の呼び出しの command に、コマンドを 1 つだけ書く
- command に `&&`・`;`・`|` を書かない
- 複数の処理を、処理ごとに別の Bash 呼び出しに分ける
- 互いに依存しない Bash 呼び出しを、同じブロックで並べて出す
- 前の出力に依存する Bash 呼び出しを、前の結果を受け取ってから出す

**Why:** ユーザーが明示的に指示した。メモリが無いと、エージェントは `cd dir && ls` のような連結コマンドや、パイプでつなぐ書き方を既定で選ぶ。

**How to apply:** Bash を呼ぶすべての場面に当てはめる。Bash の外で行う作業 (ファイルの読み書きなど) は対象外。
```

## `~/.claude/MEMORY.md` に追記する行


## 試験について
- **働く場面:** 「ビルドしてテストも実行して」のような、複数の処理を含む依頼です。
- **メモリが無いときの挙動:** `npm run build && npm test` のように連結します。
- **働くべきでない隣の場面:** 「README を読んで」のような Bash を使わない依頼です。ここでは挙動が変わらないはずです。
- **今後の試験:** ツールが使えるセッションで、上の 2 場面を足した側と足さない側で 5 回ずつ比べてください。外しても挙動が変わらない文があれば、その文は消します。
