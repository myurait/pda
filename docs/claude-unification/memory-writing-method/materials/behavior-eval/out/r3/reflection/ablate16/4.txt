```markdown
---
name: cause-names-process-not-release
description: 障害や性能劣化の原因を答えるときは、リリースや日時を原因にせず、どの処理が何をして起きたかを書く
metadata:
  node_type: memory

- 原因を答える文に、どの処理が何をして遅くなった (失敗した) のかを書く
- リリース・バージョン・日時を、原因ではなく発生時点として書く
- 処理を特定できていない原因の欄に「未特定」と書き、特定するために見るログや差分を並べる

**Why:** 決済 API のタイムアウト調査で「原因は v2.3 のリリース」と答え、ユーザーに「リリースは時点であって原因じゃない」と指摘された。
**How to apply:** 原因を尋ねる調査の回答を書くとき、まず変更差分・ログ・計測から処理を特定し、「X の処理が Y をして遅くなった」の形で書く。
```
