## `~/.claude/memory/cause-names-process.md`

```markdown
---
name: cause-names-process
description: 原因を答える文には、どの処理が何をして結果を起こしたかを書き、リリースや日付などの時点を原因として書かない
metadata:
  node_type: memory
  type: feedback
---

- 原因を答える文に、どの処理(主体)が何をして結果を起こしたかを書く
- リリース名・バージョン・日付を、原因を答える文の主語や答えとして単独で書かない
- 結果が増え始めた時点を、原因とは別の「いつから」の文に書く
- 処理を特定できていない原因の欄に「未特定」と書き、特定できた事実(時点、影響範囲)を別の文に書く

**Why:** 「v2.3 のリリースが原因」と答えたところ、ユーザーに「リリースは時点であって原因じゃない」と指摘された。
**How to apply:** 障害や性能劣化の原因調査を答えるときに使う。調査の途中経過を共有する場合は、「未特定」と書いたうえで次に調べる処理を書く。
```

## 補足

- 決済 API のタイムアウトの原因は、まだ特定できていません。いま言えるのは、11/3 の v2.3 のリリース以降にタイムアウトが増えたことだけです。
  - 原因として答えるには、v2.3 で変わった処理を調べる必要があります。たとえば差分、リリース前後のレイテンシ内訳、外部呼び出しやクエリの変化を見ます。
  - 調べ終わるまでは、原因の欄を「未特定」とします。
- メモリの書き方ルールにある Sonnet での有り無しの比較は、このセッションにツールがないので実施していません。次にツールが使えるときに試験します。
