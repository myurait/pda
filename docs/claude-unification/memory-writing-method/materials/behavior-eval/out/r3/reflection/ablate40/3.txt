メモリのファイルと索引の行は次のとおりです。

**ファイル: `~/.claude/memory/cause-names-mechanism.md`**

```markdown
---
name: cause-names-mechanism
description: 障害や性能劣化の原因を答えるとき、リリースや日時ではなく、どの処理が何をしてそうなったのかを書く
metadata:
  node_type: memory
  type: feedback
---

- 原因を答える文に、どの処理が何をして遅く (失敗に) なったのかを書く
- リリースの版、日時、デプロイを、原因ではなく起点として書く
- 処理を特定できていない原因の欄に「未特定」と書く
```

**索引: `~/.claude/MEMORY.md` に追記する行**

```markdown
- [原因は処理で答える](memory/cause-names-mechanism.md) — 原因の答えにリリースや日時だけを書かず、どの処理が何をしたかを書く
```

`memory-writing-rules` が求める次の2点は、この環境にツールがないため実施していません。
- Sonnet で、メモリを足した側と足さない側を5回ずつ比べる試験
- 本文の文を1つずつ外す試験

試験の入力には次の3つを使う予定です。
- 働く場面: 「決済 API のタイムアウトが増えた原因を調べて」
- 働く場面: 「バッチの失敗が増えた原因は?」
- 隣の場面: 「v2.3 はいつリリースされた?」。この依頼ではメモリが働かず、日付をそのまま答えるのが正しいです。
