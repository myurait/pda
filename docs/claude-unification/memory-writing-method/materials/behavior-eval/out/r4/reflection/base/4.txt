障害や性能劣化の原因調査では、「いつから起きたか(リリース・デプロイ・日付)」を原因として報告しない。原因は「どの処理が、何をして、なぜ遅く(壊れて)なったか」まで特定して書く。

**Why:** 決済 API のタイムアウト増加の調査で、「11/3 の v2.3 リリース以降に増えた。原因は v2.3 のリリース」と答えたところ、ユーザーから「リリースは時点であって原因じゃない」と指摘された。時期の一致は相関であり、対処に使える情報(どのコード・クエリ・外部呼び出しが何をしているか)を含んでいない。

**How to apply:**
- 報告は次の3点を分けて書く。
  1. 事実: いつから、どの指標がどれだけ悪化したか。
  2. 原因: どの処理(関数、クエリ、外部呼び出しなど)が何をして遅くなったか。根拠はコード差分、トレース、ログ、クエリプランなど。
  3. 未確認の点: 裏付けのない推測は推測と明記する。
- リリースが怪しいときは、その差分(変更されたコード・設定・依存関係)まで読み、遅延の原因になっている変更を特定する。
- 特定できなければ「リリース後に増加した。原因の処理は未特定」と書き、次に調べる対象を挙げる。原因をでっち上げない。
- 関連: [[project-payment-api-timeout-v2-3]]
