メモリのファイルと索引の行は次のとおりです。

**ファイル: `~/.claude/memory/cause-names-process-not-release.md`**

```markdown
---
name: cause-names-process-not-release
description: 原因を答えるとき、リリースや日時などの時点ではなく、どの処理が何をして問題を起こしたかを書く
metadata:
  node_type: memory
  type: feedback
---

- 原因を答える文に、どの処理が何をして遅く (失敗) なったのかを書く
- リリース・バージョン・日時を、問題が始まった時点として原因とは別の文に書く
- 処理を特定できていない原因の欄に「未特定」と書き、リリースを原因の代わりに書かない
```

**索引 `~/.claude/MEMORY.md` に追記する行**

```markdown
- [原因は処理で答える](memory/cause-names-process-not-release.md) — 原因を答えるとき、リリースや日時などの時点ではなく、どの処理が何をして問題を起こしたかを書く
```

**試験について(未実施)**
このセッションではツールが使えないため、Sonnet でメモリの有り無しを比べる試験は行っていません。試験に使う入力は次のとおりです。

- 働く場面:「API のエラー率が上がった原因を調べて」「ビルドが遅くなった原因は?」
  - メモリが無いときの挙動は、「原因は◯◯のリリース」と時点だけを答えることです。
- 働くべきでない隣の場面:「このエラーが始まった時期はいつ?」
  - この場面では、時点をそのまま答えるのが正しい挙動です。

「未特定」の文は、調査しても処理を特定できなかった場面でも試験する必要があります。
