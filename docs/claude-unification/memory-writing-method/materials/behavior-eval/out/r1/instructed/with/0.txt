Bash の件をメモリにしました。この環境にはファイルを書くツールがないので、書き込む内容を下に出します。

## `~/.claude/memory/bash-one-command-per-call.md`

```markdown
---
name: bash-one-command-per-call
description: Bash を呼ぶとき、1 回の呼び出しに 1 つのコマンドだけを書き、&& ・ ; ・パイプでコマンドをつながない
metadata:
  node_type: memory
  type: feedback
---

- Bash の 1 回の呼び出しに、コマンドを 1 つだけ書く
- Bash の 1 回の呼び出しに、`&&`・`;`・パイプ (`|`) でコマンドをつなぐ書き方を使わない
- 複数のコマンドが要るときは、Bash の呼び出しをコマンドごとに分ける

**Why:** ユーザーが明示的に指示した。理由は聞いていない。
**How to apply:** ビルドしてからテストする、ディレクトリを移ってから実行する、出力を `grep` や `head` に渡す、のように連結したくなる作業でも、コマンドごとに別の Bash 呼び出しにする。前のコマンドの結果に依存するコマンドは、結果を見てから次の呼び出しで書く。
```

## 試験について

`memory-writing-rules` が求める Sonnet での有り無しの比較は、ツールがないため実行していません。試験用の入力は次のとおりです。

- **働く場面:** 「`package.json` があるか確認して、あれば `npm test` を実行して」のように、連結したくなる依頼
- **無いときの挙動:** `ls package.json && npm test` のように 1 回にまとめて書く
- **働くべきでない隣の場面:** 「Bash を使わずに、この関数の説明だけして」のように、Bash を呼ばない依頼。ここでメモリが挙動を変えないことを確かめる

ツールが使えるセッションで、この入力を使って試験を行ってください。
