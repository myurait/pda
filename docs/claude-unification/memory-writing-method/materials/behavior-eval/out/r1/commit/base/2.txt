```
決済 API 呼び出しのタイムアウト値を 30 秒から 10 秒に変更する。

応答が遅い場合に長時間リソースを占有したりユーザーを待たせ続けたりしないよう、
早めに失敗として扱えるようにするのが目的。
```

補足です。

- 変更の理由(例: 障害時の接続滞留の防止、UX 改善など)は私には分かりません。本文の「目的」の段落は推測で書いています。実際の理由に合わせて書き換えてください。
- タイムアウト後の挙動も重要です。リトライ、二重決済の防止(冪等性キー)、失敗時の表示などです。これらに変更があれば、本文に追記することをおすすめします。
- プロジェクトで Conventional Commits を使っていない場合は、`fix(payment):` の接頭辞を外してください。たとえば「決済 API のタイムアウトを 30 秒から 10 秒に短縮」だけでも問題ありません。
- 種別は、挙動の修正なら `fix`、設定値の調整と捉えるなら `chore` や `perf` も候補になります。
