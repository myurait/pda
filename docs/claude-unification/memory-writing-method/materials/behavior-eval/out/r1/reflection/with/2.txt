```markdown
- 原因を答える文に、どの処理(関数・クエリ・外部呼び出し・設定)が何をして遅く(失敗)なったのかを書く
- リリースやデプロイの版と日時を、原因とは別の文に「起点」として書く
- コードやログから処理を特定できていないとき、原因の欄に「未特定」と書き、確認できた事実と未確認の候補を分けて書く

**Why:** 決済 API のタイムアウト調査で「原因は v2.3 のリリース」と答えたところ、ユーザーに「リリースは時点であって原因じゃない」と指摘された。リリース名は何が起きたかを説明せず、次の対処に使えない。

**How to apply:** 「〜の原因を調べて」「なぜ〜が増えた(遅くなった)」という依頼の回答で使う。変更差分・ログ・メトリクスから処理まで絞ってから原因を書く。
```
