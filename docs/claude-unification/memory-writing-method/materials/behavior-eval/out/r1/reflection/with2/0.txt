```markdown
- 原因を答える文に、どの処理(関数・クエリ・外部呼び出し・設定)が何をして遅くなった(壊れた)のかを書く
- リリース・デプロイ・日付・バージョンを、原因ではなく起きた時点として書く
- 変更の差分を、原因の処理を特定する手がかりとして読み、処理まで特定してから原因として書く
- 処理を特定できていないとき、「原因は未特定」と書き、確認できた範囲と未確認の点を分けて書く
```

## メモリを書く前の書き出し
これはメモリ本文の外に残す試験入力です。

- **働く場面**
  - 「タイムアウトが増えた原因を調べて」のように、障害や性能劣化の原因を尋ねる依頼
  - メモリがないと、「v2.3 のリリースが原因」のように、時点を原因として答えます。
- **働くべきでない隣の場面**
  - 「いつから増えたか教えて」のように、時点だけを尋ねる依頼
  - この場合は、時点だけを答えて構いません。
