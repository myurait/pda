```markdown
原因を答える文に、どの処理が何をして遅くなった (失敗した) のかを書く。

リリース・コミット・日時は、発生時期を述べる別の文に書き、原因の文には入れない。

処理まで特定できていないときは、特定できた範囲と未確認の範囲を分けて書く。

**Why:** 「決済 API のタイムアウトが増えた原因」を聞かれて「v2.3 のリリースが原因」と答えたところ、ユーザーに「リリースは時点であって原因じゃない」と指摘された。時点を答えても、何を直せばよいかが分からない。

**How to apply:** 原因を尋ねる依頼 (「なぜ増えた」「原因を調べて」) の回答では、ログ・差分・計測から該当の処理を特定し、その処理の動作 (例: リリースで追加したクエリが全件走査をしている) まで書いてから回答する。
```
