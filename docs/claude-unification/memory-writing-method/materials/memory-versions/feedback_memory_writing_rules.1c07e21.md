あとから自分が読んで従う文書 (メモリ・skill の SKILL.md と description・CLAUDE.md・規約文書) は、次の形で書く。

## 文の形

- 各ルールを、する操作を言い切る命令文 1 文で書く。例: 「ユーザーに見せる文はすべて日本語で書く」
- 適用範囲は目的語の名詞句に入れる。例: 「書き換えたすべてのメモリの索引行を、同じ操作で書き換える」
- 適用範囲は、成果物・実行結果・ファイルの状態など、書いた後に目で見える物で名指す
- 避けたい行動は、代わりに取る行動を言い切る文で書く
- 各文の動詞は、成果物を生む操作 (書く・消す・置き換える・出す・送る・実行する) にする。「確認する」「検討する」を使う文には、確認の結果として出す物まで書く
- 本文はルールの文だけで構成し、理由・背景・経緯・出典は変更のコミットメッセージに書く
- ルールの文は平叙の命令文で書く

既存の文は次の対応で書き換える。

- 「X したとき (場合・なら・たら) Y する」 → 「X したすべての Z に Y する」または「Z は Y の形で書く」
- 「X しない」「X 禁止」「NEVER X」 → 「W する」 (W は X の代わりに取る操作)
- 「X のため Y する」「Why: …」 → 「Y する」
- 「〜と感じたら」「迷ったら」「必要なら」「気づいたら」を含む文 → 成果物・実行結果で範囲を名指す文。名指せない文は消す
- 「発火する事象 | 実行する操作」の表 → ルールの文の箇条書き

## 本文の構成

- 本文は frontmatter の直後からルールの文の箇条書きで始め、この形式を Claude Code の既定のメモリ形式より優先する
- 1 ファイルに 1 つの失敗の型を書く
- 各文は失敗の型の水準で書き、日付・チケット番号・やり取りの引用・計測値は本文から消す
- 1 つのタスクで受けた個別の指示はそのタスクの成果物に反映し、メモリにはタスクを越えて当てはまる失敗の型だけを書く
- 関連メモリは本文の末尾に `[[name]]` で並べる

## skill の description

- skill の description は「<入力> を受けて <出力> を返す。「<依頼文の例>」「<依頼文の例>」の依頼でこの skill を使う」の形で書く
- コンポーネントスキルの description は「<入力> を受けて <出力> を返す」の 1 文で書く

## 置き場所と索引

- 相手への伝達の規則は `~/.claude/memory/` に置き、同ディレクトリの `communication-index.md` の「型 → メモリ」表に載せる
- プロジェクト横断の、成果物の正しさの規則は `~/.claude/memory/` に置き、`~/.claude/MEMORY.md` に載せる
- 1 つのプロジェクトに固有の、成果物の正しさの規則は `~/.claude/projects/<プロジェクト>/memory/` に置き、同ディレクトリの `MEMORY.md` に載せる
- 索引の各行は、メモリの規則を言い切りの命令文で要約して書く
- 新しい規則は、索引で同じ失敗の型を扱うメモリを探してそこへ追記する。新しいファイルは、索引に同じ型の無い規則にだけ作る
- メモリの新規作成・`name` の変更・本質の書き換えと同じ操作で索引を更新し、`name` を変えたメモリを指す `[[name]]` をすべて書き換える

frontmatter は次の形で書く。`description` には、そのメモリが扱う失敗の型と規則を 1 行で書く。

```yaml
---
name: <kebab-case-slug>
description: <一行要約>
metadata:
  node_type: memory
  type: feedback   # または user / project / reference
---
```
