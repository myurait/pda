# 設計ドラフト: 自走運転の計測と再有効化手順 (M4)

- Status: draft（M4 の運転設計。効力は M3 exit gate 通過後のオーナー承認で生じる）
- 日付: 2026-08-22
- 目的: goal 文書 7 節の完了条件 X1-X7 を「主張」ではなく監査イベントからの機械集計で判定できるようにし、再有効化を段階的に行う。

## 完了条件の計測方法

- X1（オーナー介入が承認・優先順位判断のみ）: 期間中のオーナー操作を承認記録・差戻し・優先度変更・停止指示に分類し、それ以外の介入（手動修復、直接 DB 操作、手動 worktree 操作）が 0 件であることをカード監査イベントと運用ログから集計する。
- X2(未授権 side effect 0 件): finalization の実行証跡と、承認記録に対応しない main 変更・デプロイ・外部送信・本番状態への試験接触の突合。敵対テストスイートの遮断イベントは「試行」であり違反に数えない。
- X3(迂回 0 件): terminal 拒否・ゲート遮断イベントのうち「遮断されなかった迂回」が 0 件であること。遮断イベント自体は正常動作の証跡として数える。
- X4（停滞の自動回復）: 停滞・claim 失効・worker 死亡の検知イベントに対し、人手の DB 修正なしで回復イベントが対応していること。
- X5（rollback 契約の機能）: 観測窓異常→自動 rollback→ポストモーテム起票の連鎖、または注入演習の合格記録。
- X6（盤面からの再構成可能性）: 期間中の全カードが出典・監査イベント・専用スレッドを持つことの機械検査。
- X7（学習ループの実証）: ポストモーテム起票→カード化→反映完了の実例が 1 件以上。

集計は決定論のレポートコマンドとして実装し、毎回同じ定義で数える。判定期間は連続 10 枚の実カードまたは 14 日間（goal 文書 7 節）。

## 段階的再有効化の手順

1. 前提: M1-M3 の exit gate 通過、敵対テストスイート全遮断、注入演習合格。
2. オーナーが committed policy（`continuity/autonomous-improvement.json`）の enabled を true へ変更してコミットし、既存の activation 契約（digest 束縛承認 + staged install）で有効化する。この経路以外の再有効化は存在しない（M0 で封鎖済み）。
3. 第 1 段階: 実行枠 1・軽リスクカードのみで運転し、X 集計を開始する。
4. 第 2 段階: 実行枠を目標値（4）へ拡大し、review_cap・host_guard の実測調整を行う。
5. 判定期間の満了時に X1-X7 の集計レポートをオーナーへ提示し、goal 完了の認定を受ける。以後は `/goal` の継続運転（改善サイクル自体の改善）へ移行する。

## オーナー関与点

- 再有効化の各段階の承認（policy コミットと activation 承認）。
- 判定期間満了時の goal 完了認定。
