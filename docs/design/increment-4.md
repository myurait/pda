# 増分 4 の設計

- 更新: 2026-09-23 JST
- 種別: 設計。増分 3 までの成果（[increment-1.md](increment-1.md) の設計を実装したもの）を入力に、判定器を実 jev に繋ぎ、可視化の最初の画面を作る。
- 物差し: `docs/requirements.md`。要件の 6（可視化）、7（UI/UX）、A6（スマホで一続きに追える）を初めて扱う。

## 1. 範囲

- 増分 3 の評価で挙げた見落とし 3 件。ACP の 2 種の通知を出来事にしない。事前プロンプトの出力指示を強める。compose のプロジェクト名を `pda` にする。
- 判定器を実 jev に繋ぐ。fixture との切り替えは環境変数で残す。
- 可視化の最初の画面（`pda-view`）。作って動かして、実際に見て決める（オーナー 2026-09-23）。専用の画面を作らない、という前の既定は取り下げる。
- 会社契約の接続、承認待ちの状態、監査（要件 9）は範囲外。

## 2. 判定器を実 jev に繋ぐ

### 2.1 実行器の可用性

実 jev は宣言された 6 実行器から選ぶが、起動していない実行器（profile `real` を上げていないとき）を選ぶとセルが応答時間切れまで止まる。判定器のラッパーは、Conductor のポーリング記録（各タスク名を最後にポーリングしたワーカーと時刻）から、直近 60 秒以内にポーリングした実行器を「可用」とし、state に `available_executors` として渡す。jev が可用でない、または type を支えない実行器を選んだら、ラッパーはその type を支える可用な実行器のうち宣言ファイル名の順で先頭のものに置き換え、`judge.answer` に置き換えの記録を残す。候補が無ければ `finish` にし理由を残す。これは決定論的な規則で、判定（推論）ではない。

未確認: ポーリング記録の API の経路。とりあえず `GET /api/tasks/queue/polldata/all` を使い、無ければタスク名ごとの `GET /api/tasks/queue/polldata?taskType=...` に切り替える。

### 2.2 問いの検証の道具

`tools/judge_probe.py`。保存済みのワークフローの記録（証拠の抜粋か、Conductor から job_id で取ったもの）と初期入力から判定器と同じ state を組み立て、実 jev に送り、4 問の答えと確信度と所要時間を JSON で出す。閾値や合否の判定は持たない。人がこの出力を見て、問いの文面と閾値を決める。

### 2.3 繰り返しの上限の一時的な変更

実 jev の e2e では費用を抑えるため、環境変数 `PDA_MAX_ROUNDS` で正本の `limits.max_rounds` を上書きできるようにする。試験用の口であり、通常は設定しない。

## 3. 可視化の最初の画面（`pda-view`）

### 3.1 何を見せるか

要件 A6 の「ある仕事について、関わった実行器、順序、受け渡しの内容が、スマホの画面から一続きで追える」を、最小の形で満たす。

- 仕事の一覧: 実行中と最近終わった仕事。状態、開始時刻、関わった実行器。
- 仕事の詳細: セルの一覧（順序、type、実行器、状態、再試行、所要時間）と、出来事の時間軸（時刻、実行器、種別、要点）。セルを選ぶとその出来事だけに絞る。
- 3 秒ごとに更新。スマートフォンの幅で崩れない。

### 3.2 どう作るか

- Python の標準ライブラリの HTTP サーバと httpx だけ。フレームワークとビルド工程を持ち込まない。画面は 1 枚の HTML と素の JavaScript。
- 読むのは Conductor の API（仕事とセル）と OpenObserve の検索 API（出来事）。書き込みはしない。
- compose のサービス `pda-view` として 5081 番を公開する。非 root。Conductor と OpenObserve に到達できる内部ネットワークに乗せる。
- スマートフォンからは Tailscale の Serve で到達させる。設定は人の手順。

### 3.3 決めないこと

見た目、情報の粒度、Conductor の UI や OpenObserve との役割分担は、動かして見てから決める。増分 4 では「見られる」ことだけを受け入れ条件にする。

## 4. 見落としの 3 件

- ACP の `available_commands_update` と `session_info_update` は出来事にしない。表に無い出来事を作らない方針は変えない。他の未知の通知は `unknown` のまま。
- 事前プロンプト（judge 以外）に「出力は JSON だけ。前後に文や説明を置かない。コードブロックの記号も付けない」を足す。分類の規則は変えない。
- compose のプロジェクト名を `pda` にする。名前付きボリュームは作り直す（増分 3 までの記録は捨てる）。イメージのタグは `local`。

## 5. 未確認

- ポーリング記録の API の経路（2.1）。
- Conductor の検索 API（終わった仕事の一覧）が Elasticsearch の索引で動くこと。増分 1 の構成で索引は有効。
- Tailscale の Serve の設定の書き方。人の手順で確かめる。

## 6. リスク

- `pda-view` の 5081 番は認証が無く、ミニ PC の ufw が無効なので LAN から誰でも見られる。意図した経路は tailnet の中からの到達で、認証は後の増分で決める。増分 4 では受け入れる。
