# owner-document

オーナーに見せる資料のHTMLは、報告係が、作業するセッションの渡した材料から作る。作業するセッションは、HTMLを作らず、材料を道具 `attach_document` で渡す。返事の本文 (`send_reply` に渡す内容) には、結論と、資料の題名と、資料で何が分かるかだけを入れる。

報告係は、材料に無い事実を足せない。資料に出したいことは、すべて材料に入れる。

## 材料の先頭に入れること

- だれが、だれに、何のために見せる資料か。
  - オーナーに判断を求める資料
  - オーナーがほかの人に見せる資料
  - オーナー自身の整理のための資料
- オーナーが依頼で使った語 (題名と見出しに使う語)。

## 判断を求める資料の材料

判断を1つずつ分け、判断ごとに次を入れる。

1. 決めること (問いの形)
2. 今の状態
3. 判断に要る事実
4. 選択肢と、選んだ場合に起きること
5. 推奨と、その根拠の事実 (根拠を事実で言えないときは、推奨が無いことを入れる)

見た目で違う選択肢は、違いが分かる説明か、絵のファイルの場所を入れる。

## 図や表にしたい内容

- 構成 (層、流れ、部品のつながり) を確かめてもらう資料では、何と何が、どの出来事でつながるかを、1つずつ文で入れる。
- 処理の順序は、だれが、だれに、何を渡すかを、起きる順に入れる。
- 表にしたいデータは、行と列が分かる形で入れる。

## 材料の書き方

- 事実、識別子、数値、パス、コマンドの出力、リンクは、省かずに入れる。
- 作業の中だけで使った呼び名は、何のことかの説明を添える。
