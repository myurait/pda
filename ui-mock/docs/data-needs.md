# 画面が要る情報と操作の入力

これは次の増分で API を設計するための一覧である。モックは通信しない。確認対象は `docs/requirements.md`、`docs/design/basic-design-proposal.md` の Conductor の構成、`registry/executors/*.yaml`、`registry/types/*.yaml`、`src/pda_wrapper/events.py` の出来事の種別一覧に限定した。現行 API がすでに返すという意味ではない。

「取れる」は、基本設計で保存が明記された Conductor の記録、実在する宣言、または列挙された出来事に必要な材料があるという意味である。出来事の payload の実装や全フィールドは調査していない。記録間の関係、専用の意味フィールド、オーナー操作の永続化が必要なものは「新しく要る」と明記する。本文にイベント全件やツールの全出力は出さない。

## 1. 状態と言葉の対応

以下は表示側の対応案。Conductor の機械状態をタスクの完了・中止へそのまま変換しない。

| 対象 | 画面の状態 | Conductor の記録からの対応 | 追加の意味 |
|---|---|---|---|
| セル | 待機 | `SCHEDULED` | 追加済みセルの依存先と、開始条件が新しく要る |
| セル | 動作中 | `IN_PROGRESS` | 担当実行器と開始時刻を関連付ける |
| セル | 終わった | `COMPLETED` | 作業の終了。タスクの完了ではない |
| セル | 失敗した | `FAILED`、`FAILED_WITH_TERMINAL_ERROR`、`TIMED_OUT` | 失敗理由を保持し、後続の判定器 A に関連付ける |
| セル | 中断した | `CANCELED` | オーナー中断か実行の終了かを出所と理由で区別 |
| セル | 終わった／注記あり | `COMPLETED_WITH_ERRORS`、`SKIPPED` | 成功と同一視せず「任意セルの失敗」「実行を省略」を別注記。今回の見本では使用しない |
| タスク | 進行中 | 機械状態だけでは決めない | 動作中または次の作業が予約されている。新しく要る：タスク集約状態 |
| タスク | 入力待ち | `COMPLETED` や `FAILED` だけからは決めない | 報告があり、問い／自動作業なし／コア規則停止の理由を持つ。新しく要る |
| タスク | 完了・中止 | 対応なし | オーナーが記録した状態・時刻。新しく要る |

機械状態名の照合資料：[Conductor Task lifecycle](https://conductor-oss.github.io/conductor/devguide/architecture/tasklifecycle.html)、[Workflow API](https://conductor-oss.github.io/conductor/documentation/api/workflow.html)。参照日は 2026-09-25。表はこれらの状態を要件の表示語へ写す設計上の判断であり、使用中の Conductor 版との接続検証は次の増分で行う。

| 報告なし・途中の要約 | 現在回、動作セル、直近出力の要点 | Conductor の記録＋出来事の流れ。新しく要る：最終報告と区別した要約 | 数秒ごと |

## 8. 送る必要がある情報

すべての操作に対象 ID、操作の識別子、オーナー由来であること、入力時刻が必要。以下は API の入出力項目案であり、URL や HTTP メソッドは定めない。現在の完了・中止記録とオーナーセルの永続化契約は新しく要る。

| 操作 | 送る情報 | 受け付けたあと画面が必要とする情報 |
|---|---|---|
| 1. 実行を中断 | taskId、任意の理由／次の指示 | 中断対象の cellId 全件、受理状態、判定器 A の cellId、中断理由の参照 |
| 2. 指示を重ねる | taskId、指示原文 | ownerCellId、適用する次の roundId、入力待ちから再開した状態 |
| 3. セルを挿し込む | taskId、基準cellId、位置（直後／並列）、type、入力原文 | cellId、接続関係、branchId、出所=オーナーの操作 |
| 4. セルへ追加指示 | taskId、cellId、入力原文、完了・合流済みの場合は破棄と再開の確認 | inputId、対象セルの試行、破棄した後続セル・報告・成果物、再開状態。確認なしでは変更しない |
| 5. セルを再試行 | taskId、元 cellId、選んだ executorId、元の type と入力への参照 | 新しい cellId、元セルとの関係、試行履歴、出所=オーナーの操作 |
| 6. 初期の指示を書き換える | taskId、新しい指示、適用方法（以後／最初から） | ownerCellId、適用先、やり直す場合は中断したセルと新しく追加したセル |
| 7. 完了として記録 | taskId、状態=完了 | オーナーの記録時刻、タスク状態、動作セルがあれば終了対象 |
| 8. 中止として記録 | taskId、状態=中止 | オーナーの記録時刻、タスク状態、止めた実行とセル |
| 実行器を起こす | executorId、操作=起動 | 生死、観測時刻、操作の受付と完了の区別 |
| 実行器を止める | executorId、操作=停止、確認時点の担当セル ID 群 | 中断された全セル、各判定器への関連、実行器の生死 |
| 問いへの一括返答 | taskId、reportId、全 questionId と回答。選択式にも自由文を許容 | 全件をまとめて保存し、1つの ownerCellId と次の judgeCellId、入力待ちからの除外。不足・再送・過去報告は状態変更しない |
| 新しいタスク | 指示原文、任意 workdir | taskId、初期 ownerCellId、先頭 judgeCellId、受付時刻 |

同一操作の再送と、確認後に対象が変わったことを識別するため、操作 ID と対象の版を API 設計時に検討する。回数上限などの入力欄は加えない。

## 9. モックで代用しているもの

型は `src/mock/model.ts`、宣言の写しと見本は `seed.ts`、段階進行と介入は `actions.ts` にある。ブラウザのローカル保存は実サーバの状態を表さない。経過と時刻、稼働、出力、問い、成果物は見本。1 歩ごとの遷移は判定器やオブザーバーへの実呼び出しを行わない。判定器、報告担当、タスクオブザーバーはrole設定の実行器に模擬的に担わせる。オブザーバーは指示だけを出し、作業は別の作業セルが行う。

## 10. role設定

報告担当、判定器、タスクオブザーバーごとに、roleId、executorId、model、注入プロンプト、skill指定を保存する。タスク作成時には報告担当を受け取らない。roleと実行器の割り当て、モデル指定と注入内容の契約は新しく要る。skill登録はid、名前、参照先、説明を持ち、roleのskill指定には登録IDの配列を使用する。生成したセルには使用した設定を保持する。

セルの追加は taskId、基準のcellId、位置（直後／並列）、type、入力を受け取り、追加したcellIdと接続を返す。実行nや将来の回の番号を操作の引数にしない。

## 11. 2026-09-26レビューで確定した追加の表示契約

1. 通常の入力待ちは警告にしない。中断による入力待ちだけ黄色三角で表示する。理由の表示語は「判断を求めています」「次の指示を待っています」「タスクが中断されています」。`#/inbox`は一覧のみで、選択先はタスクの報告タブ。
2. 報告担当の出力には一覧用の短い`summary`と、判断に必要な`artifactIds`を追加する。本文の先頭から自動抽出しない。
3. `lastInstructionAt`は最終指示の受理時刻、`waitingSince`は待ち状態へ入った時刻。待機時間は現在から`waitingSince`を引く。実行時間は`lastInstructionAt`からページを開いた時点まで、待機中は`waitingSince`まで。再開時に待機開始を消し、新しい指示受理時刻を保存する。
4. 試行ごとの実入力を保存し、完了セルから再開する際も前の試行の入力・出力を参照できるようにする。破棄対象は対象セルの後続に依存するセル・報告・成果物であり、依存しない並列セルは保持する。
5. 各実行器は個別の利用状況取得スクリプト設定を持つ。画面へ渡す応答は下記の配列。`title`と`value`は必須、`limit`と`alert`は省略可能。値と上限は文字列または数値で、単位を固定しない。alertは応答の指定のみを表示に使用し、値から推定しない。

```json
[
  {"title": "5時間制限", "value": "75%", "limit": "100%", "alert": "warning"},
  {"title": "週制限", "value": "95%", "limit": "100%", "alert": "critical"},
  {"title": "クレジット利用額", "value": "1$"}
]
```

このモックではスクリプト設定と応答JSONの見本をブラウザーに保存して描画する。スクリプト実行、実契約の残量取得、報告用エージェントへの実呼び出しは未接続。

時間表示はページを開いた時点を基準に算出し、表示中の秒ごとの更新は行わない。タスク一覧では実行時間と待機時間を別列にし、状態・現在の動き・待ち理由は状態列に統合する。最終更新は日付と時刻の二段表示。
